Java Core · Runtime Architecture

JDK vs JRE vs JVM & Compilation

How Java translates your readable source code into platform-independent bytecode and executes it efficiently on any machine.

2. Quick Role Comparison

JVM (Virtual Machine)

The abstract machine that executes bytecode. Platform-dependent (there are separate JVMs for Windows, macOS, Linux).

JRE (Runtime Environment)

JVM + core standard libraries. It is everything needed to run an already-compiled Java application.

JDK (Development Kit)

JRE + developer tooling (compiler javac, archiver jar, debuggers). Required by developers to write and build code.

Modern Java Note (Java 9+): Standalone JRE installers were deprecated starting with Java 11. Today, developers download the JDK, and tools like jlink create custom, minimal runtimes packaged directly with modern containers or apps.

4. What is Java Bytecode?

Bytecode is an intermediate, binary instruction set designed specifically for the JVM rather than any physical hardware chip. It shields your application from OS-specific instruction sets.

Java Source (App.java) 
public int add(int a, int b) {
    return a + b;
}
Compiled Bytecode (javap -c) 
0: iload_1     // load arg a
1: iload_2     // load arg b
2: iadd        // execute sum
3: ireturn     // return result

5. How the JVM Executes Code: Interpreter vs JIT

To avoid the classic slowdown of interpreted languages, modern JVMs (HotSpot) combine an Interpreter with a Just-In-Time (JIT) Compiler:

  • Interpreter: Starts executing bytecode immediately line-by-line. Fast startup time, but slower sustained throughput.
  • Hotspot Profiler: Monitors which methods or loops run frequently ("hot spots").
  • JIT Compiler (C1 / C2): Compiles those frequently executed bytecode blocks directly into native CPU machine instructions and caches them in memory. Next time that method is called, it runs at native C/C++ speeds.
  • Garbage Collector (GC): Runs in the background to automatically free heap memory by removing unreachable objects.

7. Quick Interview Takeaways

  • Is Java compiled or interpreted? Both. It compiles .java to bytecode via javac, then the JVM interprets and JIT-compiles that bytecode into native machine instructions.
  • Is the JVM platform-independent? No. Bytecode is platform-independent, but the JVM itself is platform-specific. Windows, macOS, and Linux each require their own JVM binary.
  • Why not compile directly to native machine code? Bytecode enables WORA portability and allows dynamic runtime optimizations (like JIT inlining and adaptive profiling) tailored to the actual running workload.
