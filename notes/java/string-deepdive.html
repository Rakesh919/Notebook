Java Core · Memory Management & String Internals

String vs StringBuilder vs StringBuffer

The definitive guide to Java string handling, JVM memory allocation, thread-safety trade-offs, String Constant Pool mechanics, and production-level performance optimization.

1. Introduction

Handling textual data efficiently is a core requirement of almost every enterprise Java application. Java provides three primary classes in the java.lang package for managing character sequences: String, StringBuilder, and StringBuffer.

1. String

Immutable sequence of characters. Every modification produces a brand-new object instance in memory.

2. StringBuilder

Mutable sequence of characters designed for single-threaded dynamic operations without synchronization overhead.

3. StringBuffer

Thread-safe, mutable sequence of characters where methods are synchronized to prevent data corruption in multi-threaded environments.

Why Java Provides Three Classes:
A single string class cannot optimize for immutability, thread-safety, and raw performance simultaneously. String delivers safety, hash stability, and security; StringBuilder delivers maximum execution speed; StringBuffer provides thread-safe mutability.

2. String Deep Dive

The String class represents an immutable sequence of characters. In Java 9, its internal storage was migrated from a char[] array to a byte array (byte[]) with a compact encoding flag to halve memory usage for ASCII/Latin-1 text.

// Java 9+ internal declaration in java.lang.String
public final class String implements java.io.Serializable, Comparable<String>, CharSequence {
    private final byte[] value;
    private final byte coder; // LATIN1 (0) or UTF16 (1)
    private int hash; // Cached hash code
}

Why String is Immutable in Java

  • String Constant Pool (SCP): Enables sharing identical string literals across the JVM, saving massive amounts of Heap memory.
  • Security: Strings carry critical security parameters (database URLs, passwords, network sockets, file paths). Immutability prevents malicious code from mutating these values after validation.
  • Thread Safety: Immutable objects are inherently thread-safe and can be shared freely across multiple threads without synchronization.
  • HashCode Caching: Because the value cannot change, the hashCode() is computed once and cached (hash field), making String exceptionally fast as a key in HashMap and HashSet.
Disadvantage of String Immutability: Concatenating or modifying strings generates intermediate orphaned objects on the heap, triggering frequent Garbage Collection (GC) pauses if executed repeatedly.

3. StringBuilder Deep Dive

Introduced in Java 5, StringBuilder is a mutable character sequence designed as a direct, non-synchronized drop-in replacement for StringBuffer.

// Basic usage of StringBuilder
StringBuilder sb = new StringBuilder("Initial");
sb.append(" Data");    // Modifies internal buffer directly
sb.insert(0, "Header: ");
sb.delete(0, 8);
sb.reverse();
String result = sb.toString(); // Creates final immutable String

Capacity Growth Mechanism

StringBuilder maintains an internal dynamic array (default initial capacity = 16 characters). When appended data exceeds the current buffer size, the internal capacity grows automatically according to the formula:

New Capacity Formula: New Capacity = (Old Capacity * 2) + 2
If (Old Capacity * 2) + 2 is still insufficient, the capacity expands directly to the exact required size.

4. StringBuffer Deep Dive

StringBuffer has been part of Java since JDK 1.0. It provides a mutable character buffer identical to StringBuilder, but every major method is marked with the synchronized keyword to enforce thread safety.

// Simplified JDK source view of StringBuffer
public final class StringBuffer extends AbstractStringBuilder implements CharSequence {
    @Override
    public synchronized StringBuffer append(String str) {
        super.append(str);
        return this;
    }
}
Performance Cost of Synchronization:
Even in single-threaded environments, calling synchronized methods forces the JVM to perform monitor lock acquisitions and releases, incurring a significant performance penalty compared to StringBuilder.

6. Why String Should Not Be Used Inside Loops

Performing string concatenation using the + operator inside loops is one of the most common performance anti-patterns in Java.

Bad Example (Quadratic Overhead O(N²)):

// DON'T DO THIS IN PRODUCTION
String result = "";
for (int i = 0; i < 10000; i++) {
    result += i; // Creates a new StringBuilder and String object per iteration
}

Under the hood, the compiler rewrites result += i as result = new StringBuilder().append(result).append(i).toString(). In every iteration, the entire existing string is copied into a new buffer, causing $O(N^2)$ time complexity and generating tens of thousands of short-lived objects that trigger GC overhead.

Good Example (Linear Time O(N)):

// PRODUCTION-READY PATTERN
StringBuilder sb = new StringBuilder(10000 * 4); // Pre-sized capacity
for (int i = 0; i < 10000; i++) {
    sb.append(i);
}
String result = sb.toString();

7. String Constant Pool (SCP)

The String Constant Pool is a special reserved memory region inside the Java Heap (moved from PermGen to Heap in Java 7). It stores literal strings to optimize memory consumption via sharing.

Literal Allocation vs New Keyword Allocation

1
String s1 = "Java"; → Checks SCP. If absent, creates "Java" in SCP. s1 references SCP instance.
2
String s2 = "Java"; → Finds "Java" in SCP. s2 points directly to the existing SCP instance (s1 == s2 evaluates to true).
3
String s3 = new String("Java"); → Forces creation of a distinct non-pool object in normal Heap memory (s1 == s3 evaluates to false).
String Interning (s3.intern()):
Calling s3.intern() queries the SCP. If a string equal to s3 exists in the pool, its reference is returned. Otherwise, s3 is added to the pool and returned.

8. Internal Memory Diagrams

JVM Heap & SCP Object Reference Layout

1. Immutable String Re-assignment

String s = "A"; s = s + "B";

Creates object "A" in SCP. Concatenation produces a brand-new object "AB" in Heap. Original "A" remains unmodified.

2. StringBuilder / StringBuffer Mutation

StringBuilder sb = new StringBuilder("A"); sb.append("B");

A single StringBuilder object is allocated on the Heap. The internal byte array expands/mutates in-place without creating new objects.

10. When to Use Which?

Use String For:
  • Constants, ENUMs, and configuration parameters.
  • HashMap keys or HashSet elements.
  • DTO fields, API responses, and domain entities.
Use StringBuilder For:
  • Dynamic string building inside loops or recursive methods.
  • Constructing SQL queries, JSON/XML payloads, or HTML templates.
  • Formatting log lines or reading files sequentially.
Use StringBuffer For:
  • Shared mutable strings accessed concurrently across threads without external synchronization.
  • Maintaining compatibility in legacy JDK codebases.

11. Top 25 Interview Questions

Q1: Why is String immutable in Java?
For String Pool memory sharing, security (passwords/network URIs), thread safety, and hashcode caching.
Q2: How many objects are created by `String s = new String("Hello")`?
One or two. One object is created in Heap memory. If "Hello" is not already in the String Constant Pool, a second object is created in the SCP.
Q3: Difference between String Pool and Heap?
The String Constant Pool is a specialized area inside the Heap managed separately by the JVM to deduplicate literal string values.
Q4: Why is String preferred as a HashMap key?
Immutability guarantees that the key's hashcode will never change after insertion, preventing key corruption or lost bucket references.
Q5: What is the difference between `==` and `.equals()` for Strings?
`==` compares memory references (whether two variables point to the exact same object). `.equals()` compares character content.
Q6: What is String interning?
It manually moves or retrieves a string from the String Constant Pool using the `intern()` method.
Q7: Is StringBuilder thread-safe?
No. It lacks synchronization; concurrent modifications produce data races or array index out-of-bounds exceptions.
Q8: Why is StringBuffer slower than StringBuilder?
Because every core method in StringBuffer is marked `synchronized`, incurring thread locking overhead.
Q9: What changes were made to String internal implementation in Java 9?
Replaced `char[]` (2 bytes per char) with `byte[]` and a `coder` flag (Compact Strings) to save 50% memory for ASCII strings.
Q10: Can we make StringBuilder thread-safe externally?
Yes, by wrapping access inside custom synchronized blocks or reentrant locks.
Q11: What is the default capacity of StringBuilder?
16 characters.
Q12: How does StringBuilder resize its internal buffer?
New capacity = `(Old Capacity * 2) + 2`.
Q13: Does String concatenation with `+` use StringBuilder automatically?
Yes, the Java compiler rewrites single-line `+` operations using `StringBuilder` (or `StringConcatFactory` in Java 9+).
Q14: What is `StringConcatFactory`?
A JDK 9 feature using `invokedynamic` to optimize single-line string concatenation dynamically.
Q15: What happens if you pass a negative capacity to StringBuilder?
Throws a `NegativeArraySizeException`.
Q16: Can a class override String methods?
No, `String` is marked `final`, preventing subclassing or method overriding.
Q17: What is CharSequence?
A standard read-only interface implemented by `String`, `StringBuilder`, and `StringBuffer`.
Q18: Should sensitive data (passwords) be stored in String or char[]?
In `char[]`. Strings remain in memory until GC runs and cannot be zeroed out manually due to immutability.
Q19: What is the result of `"Hello" + null`?
`"Hellonull"`.
Q20: How does `String.repeat(n)` work in Java 11?
Returns a new string consisting of the original string repeated `n` times.
Q21: Difference between `isEmpty()` and `isBlank()`?
`isEmpty()` checks if length is 0. `isBlank()` (Java 11+) checks if length is 0 or if the string contains only whitespace.
Q22: Is String class serializable?
Yes, it implements `Serializable`, `Comparable`, and `CharSequence`.
Q23: What is the time complexity of `StringBuilder.append()`?
Amortized $O(1)$.
Q24: What happens if StringBuilder capacity overflows Integer.MAX_VALUE?
Throws an `OutOfMemoryError`.
Q25: Can String be used in a `switch` statement?
Yes, since Java 7 (evaluates string `.equals()` and `hashCode()`).

12. Common Mistakes

1. Using `+` in Loops: Creates thousands of unwanted intermediate `StringBuilder` and `String` instances.
2. Comparing Strings using `==`: Compares memory references instead of value content. Always use `.equals()`.
3. Unnecessary Use of StringBuffer: Using `StringBuffer` in local single-threaded methods wastes CPU cycles on unneeded lock acquisition.

13. Best Practices

  • Pre-size StringBuilder initial capacity when the final approximate size is known: new StringBuilder(estimatedSize).
  • Use char[] or byte[] for passwords or encryption keys, zeroing out the array immediately after use.
  • Use String.join() or StringJoiner for joining collections with delimiters instead of manual loop appending.

14. Revision Cheatsheet

String: Immutable · Thread-safe · Cached hash · String Pool enabled · Use for domain models & constants.

StringBuilder: Mutable · Fast · Non-synchronized · Use for loops, builders & local processing.

StringBuffer: Mutable · Synchronized · Thread-safe · Legacy multi-threaded use.
