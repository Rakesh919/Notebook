JVM Memory Model

Where objects actually live while your program runs, and why it matters for performance and interviews.

The main regions

Heap

Every object you create with new lives here. Shared across all threads. Garbage collected.

Stack

One per thread. Holds method call frames, local variables, and references to heap objects.

Metaspace

Class metadata — method bytecode, static fields. Replaced PermGen since Java 8.

PC Register & native stacks

Per-thread bookkeeping for the instruction pointer and native method calls.

Young vs Old generation

The heap itself is split further. Most objects die young, so the JVM optimizes for that: new objects go into Eden, survive a collection into Survivor space, and only get promoted to the Old generation if they stick around. This is why minor GCs (young gen) are frequent and cheap, while major GCs (old gen) are rarer and more expensive.

Why this comes up in interviews

Common follow-ups: what causes a StackOverflowError vs an OutOfMemoryError (stack depth vs heap exhaustion), and how garbage collection decides an object is unreachable (reachability from GC roots, not just reference counting).
