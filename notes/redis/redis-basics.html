1. Introduction

Redis (Remote Dictionary Server) is an open-source, in-memory data structure store used as a database, cache, streaming engine, and message broker. Created by Salvatore Sanfilippo in 2009 to scale LLOOGG (a real-time web log analyzer), Redis solved the severe disk I/O bottlenecks inherent in traditional relational database systems.

Why Relational Databases Struggle

Traditional RDBMS (MySQL, PostgreSQL) rely on disk-backed B-Trees or LSM Trees. Every query involves random disk seeks, complex query parsing, table locking, and buffer pool synchronization, capping throughput at thousands of operations per second per node.

The Redis Paradigm Shift

By keeping the primary dataset entirely in RAM and operating on optimized data structures (Hash Tables, Skip Lists, Radix Trees), Redis achieves sub-millisecond latencies and processes over 100,000 requests per second per single thread.

2. Why Redis? Performance Drivers

Application slowness stems primarily from latency gaps in hardware storage tiers. Accessing RAM takes nanoseconds (~100 ns), whereas accessing NVMe SSDs takes microseconds (~50,000 ns) and traditional spinning disks take milliseconds (~10,000,000 ns).

Latency Memory Hierarchy Gap

1
L1/L2 Cache: ~1-5 nanoseconds
2
RAM (Redis Primary Location): ~100 nanoseconds (Ultra-Fast Path)
3
NVMe SSD (Disk DBs): ~50,000 nanoseconds (500x slower)
4
Mechanical Disk: ~10,000,000 nanoseconds (100,000x slower)

3. Redis Architecture & Reactor Pattern

Redis executes commands on a single-threaded execution core using an asynchronous, non-blocking I/O multiplexing event loop known as the Reactor Pattern (built on Linux epoll, macOS kqueue, or Solaris evport).

Why Single-Threaded Execution Works:
  • Zero Context Switching: Eliminates CPU thread context switching overhead and CPU cache invalidations.
  • No Locking Overhead: Avoids mutexes, spinlocks, and race conditions across key-value operations.
  • I/O Multiplexing: A single OS thread monitors thousands of socket connections simultaneously, executing commands sequentially as network packets arrive.

4. How Redis Works Internally

The lifecycle of a Redis command request executes through a high-performance networking pipeline:

1
Client Connection: Client establishes a TCP connection (default port 6379).
2
Event Loop Registration: Socket file descriptor is registered with aeCreateFileEvent targeting read events.
3
RESP Protocol Parsing: readQueryFromClient reads raw TCP data and parses the RESP (REdis Serialization Protocol) array.
4
Command Table Lookup: Redis looks up the parsed command string in the redisCommandTable hash map.
5
Key Lookup & Memory Read: Redis inspects the keyspace dictionary (db->dict) for matching data objects.
6
Command Execution: Executes the specialized C function (e.g., getCommand, hsetCommand).
7
Output Buffer Write: Serializes the response into the client's output buffer and flushes it to the socket.

5. Memory Management & Encodings

Redis manages memory using specialized dynamic allocators like jemalloc (or tcmalloc). To maximize memory efficiency, every value stored in Redis is wrapped inside a generic redisObject structure.

typedef struct redisObject {
    unsigned type:4;       // OBJ_STRING, OBJ_LIST, OBJ_HASH, OBJ_SET, OBJ_ZSET
    unsigned encoding:4;   // OBJ_ENCODING_RAW, OBJ_ENCODING_INT, OBJ_ENCODING_ZIPLIST, etc.
    unsigned lru:24;       // LRU timestamp or LFU frequency for cache eviction
    int refcount;          // Reference count for shared memory optimization
    void *ptr;             // Pointer to actual underlying data structure
} robj;

8. Persistence: RDB vs AOF

Redis provides two distinct persistence models to write in-memory data to disk:

RDB (Redis Database Snapshots)

Creates compact, point-in-time binary snapshots of the dataset at specified intervals via OS fork() and Copy-On-Write (COW). Extremely fast recovery; minimal runtime performance impact.

AOF (Append-Only File)

Logs every write command received by the server to an append-only file. Provides near-zero data loss options (fsync everysec / always) and features automatic background rewrites.

Dimension RDB Snapshotting AOF Logging
Data Recovery Speed Ultra-fast (directly loads binary structures into memory) Slower (replays millions of write commands sequentially)
Data Loss Exposure Higher (loses all writes since last snapshot interval) Minimal (typically maximum 1 second of data loss)
File Size Compact, highly compressed binary dump Larger text log (mitigated by AOF Rewrite)

9. Replication Architecture

Redis uses a master-replica asynchronous replication model to provide read scalability and redundancy.

Replication Synchronization Flow

1
Replica connects to Master and issues PSYNC <replication_id> <offset>.
2
Full Sync (Cache Miss/New Replica): Master runs background RDB save (bgsave), sends snapshot binary stream to replica, and streams ongoing write commands buffered in repl-backlog-buffer.
3
Partial Sync (Re-connection): If disconnection was brief and requested offset exists in Master's circular backlog buffer, Master streams missing delta bytes only.

10. Redis Sentinel High Availability

Redis Sentinel provides high availability for Master-Replica setups without manual intervention.

Core Responsibilities of Sentinel
  • Monitoring: Constantly checks if Master and Replica instances are responding to PING.
  • Notification: Alerts system administrators or external discovery agents via Pub/Sub.
  • Automatic Failover: Promotes a Replica to Master if the Master suffers a Subjectively Down (SDOWN) and Objectively Down (ODOWN) quorum consensus.
  • Configuration Provider: Clients query Sentinels to discover the current Master IP address.

11. Redis Cluster & Hash Slots

Redis Cluster provides horizontal scaling and data sharding across multiple Master nodes without a central proxy.

16,384 Hash Slots Mechanics:
The entire keyspace in Redis Cluster is partitioned into 16,384 fixed hash slots. When storing a key, Redis calculates the slot using the CRC16 algorithm:
slot = CRC16(key) mod 16384
Master nodes split responsibility for these 16,384 slots (e.g., Master 1 holds slots 0–5460; Master 2 holds 5461–10922; Master 3 holds 10923–16383).

12. Redis Transactions & Optimistic Locking

Redis transactions group commands into a sequential execution block using MULTI, EXEC, DISCARD, and WATCH.

13. Lua Scripting

Lua scripts execute directly inside the Redis event loop, providing transactional atomicity and eliminating network round-trips.

-- Atomic Rate Limiter Script in Lua
local key = KEYS[1]
local limit = tonumber(ARGV[1])
local current = tonumber(redis.call('GET', key) or '0')

if current + 1 > limit then
    return 0 -- Block request
else
    redis.call('INCRBY', key, 1)
    if current == 0 then
        redis.call('EXPIRE', key, 60)
    end
    return 1 -- Allow request
end

14. Pub/Sub Engine

Redis Pub/Sub acts as a lightweight message fan-out broker where publishers send messages to named channels and subscribed clients receive them in real time.

Pub/Sub Limitation: Redis Pub/Sub is fire-and-forget. Messages are not persisted on disk. If a subscriber drops connection, missed messages are permanently lost. Use Redis Streams for message persistence and consumer groups.

15. Redis Streams & Consumer Groups

Redis Streams is an append-only log data structure modeled after Apache Kafka, featuring consumer groups, message IDs, pending entries lists (PEL), and explicit acknowledgement (XACK).

16. Caching Patterns & Strategies

1. Cache-Aside (Lazy Loading)

App checks Redis first. On cache miss, reads from DB, writes result back to Redis, and returns data.

2. Write-Through

App writes data to Cache. Cache synchronously updates the DB before acknowledging success.

3. Write-Behind (Write-Back)

App writes to Cache instantly. A background worker asynchronously flushes updates to DB in batches.

17. Cache Eviction Policies

When Redis reaches its configured maxmemory threshold, it executes the selected eviction policy:

  • noeviction: Returns out-of-memory errors on new write attempts.
  • allkeys-lru: Evicts Least Recently Used keys across all stored keys (Standard Production Cache setting).
  • volatile-lru: Evicts LRU keys that have an explicit TTL expiration set.
  • allkeys-lfu: Evicts Least Frequently Used keys across all keys.
  • volatile-ttl: Evicts keys with shorter remaining TTL values.

18. Key Expiration Mechanics

Redis purges expired keys using a hybrid approach:

1. Passive Deletion

When a client attempts to read an expired key, Redis catches the expired TTL state, deletes the key immediately, and returns null.

2. Active Active-Random Scanning

10 times per second, Redis randomly tests 20 keys with TTLs from the expiration dictionary. If more than 25% are expired, it repeats the process continuously.

19. Low-Level Internals & Structures

Redis implements unique internal structural types in C to minimize RAM usage:

  • SDS (Simple Dynamic String): Replaces C null-terminated strings; stores string length explicitly to allow $O(1)$ length lookups and binary safety.
  • ZipList / ListPack: A sequential memory block storing integers and small strings without pointer overhead.
  • SkipList: Probabilistic alternative to balanced trees, driving Sorted Sets with $O(\log N)$ search speeds.

20. Redis Networking & RESP Protocol

RESP (REdis Serialization Protocol) is a simple, human-readable text-based wire protocol over TCP:

# How "SET name Alice" is transmitted over TCP in RESP2:

$4\r\n

24. Performance Optimization

  • Pipelining: Batch multiple commands together into a single TCP write buffer to eliminate network latency round-trips.
  • Slowlog Monitoring: Debug commands exceeding thresholds using SLOWLOG GET 10.
  • Avoid Blocking Commands: Never run KEYS * or FLUSHALL in production. Use SCAN instead.

29. Common Production Mistakes

1. Running `KEYS *` in Production: Blocks the single-threaded event loop, freezing all client operations. Use SCAN.
2. Unbounded Memory Usage: Omitting maxmemory limits and setting noeviction causes the OS to trigger OOM Killer process termination.

30. Production Best Practices

  • Always enforce structured key namespaces (e.g. v1:tenant:users:1001).
  • Set explicit TTL values on cache keys to prevent memory bloat[cite: 13].
  • Configure connection pools (Lettuce/Jedis) properly with appropriate timeouts[cite: 13].

31. 75+ Senior Interview QA

Q1: Is Redis strictly single-threaded?
No. While main key-value command execution runs on a single event-loop thread, Redis utilizes background threads for heavy tasks like asynchronous file closing, AOF fsync calls, and lazy key deletion (UNLINK). Redis 6+ also introduced multi-threaded network I/O parsing.
Q2: What is the difference between SDOWN and ODOWN in Sentinel?
SDOWN (Subjectively Down) occurs when an individual Sentinel instance loses contact with the Master. ODOWN (Objectively Down) occurs when a configured quorum of Sentinels agree that the Master is unreachable, triggering failover.
Q3: How many hash slots exist in Redis Cluster?
16,384 fixed slots.
Q4: What is the difference between LRU and LFU?
LRU (Least Recently Used) evicts keys based on time elapsed since last access. LFU (Least Frequently Used) evicts keys based on frequency access count.
Q5: What command replaces KEYS * safely?
SCAN (or HSCAN, SSCAN, ZSCAN).
Q6: What is a ZipList?
A specially encoded memory block holding small hash/list/zset entries sequentially without pointer overhead.
Q7: What is the purpose of the Redlock algorithm?
To guarantee fault-tolerant distributed locking across multiple independent Redis master nodes.
Q8: How does Redis support transactions?
Using MULTI, EXEC, DISCARD, and optimistic locking via WATCH.
Q9: What is copy-on-write (COW) during RDB save?
The OS forks the Redis process. Memory pages are shared between parent and child until written to, protecting memory footprint during snapshotting.
Q10: What is the maximum size of a String value in Redis?
512 Megabytes.
Q11: What is RESP?
REdis Serialization Protocol; the wire protocol used for client-server TCP communication.
Q12: How does UNLINK differ from DEL?
DEL deletes keys synchronously on the main thread. UNLINK removes keys from the keyspace synchronously but reclaims memory asynchronously in a background thread.
Q13: What is Cache Avalanche?
When a vast number of cached items expire simultaneously, driving massive fallback database spikes. Solved by adding jitter to TTL values.
Q14: What is Cache Penetration?
When queries for non-existent keys repeatedly bypass cache and hit the database. Solved via Bloom Filters or caching null results.
Q15: What is Cache Breakdown (Stampede)?
When a high-traffic hot key expires, causing concurrent requests to hit the database simultaneously. Solved via mutex locks.
Q16: Difference between RDB and AOF?
RDB is point-in-time binary snapshots; AOF is a continuous append-only write log.
Q17: How does Redis handle memory fragmentation?
By utilizing dynamic allocators like jemalloc and running active defragmentation (activedefrag yes).
Q18: What is a SkipList?
A probabilistic data structure used alongside hashtables to back Redis Sorted Sets with O(log N) lookup capabilities.
Q19: What is the difference between MOVED and ASK redirects in Redis Cluster?
MOVED indicates a permanent relocation of a hash slot to another node. ASK indicates a temporary relocation during active slot migration.
Q20: Can Lua scripts be interrupted?
Only via SCRIPT KILL if the script has not executed write operations. Writes require SHUTDOWN NOSAVE.
Q21: What is a Bloom Filter?
A probabilistic data structure used to test set membership with zero false negatives and low memory usage.
Q22: How does HyperLogLog achieve cardinality estimation?
By tracking maximum leading zero bit counts in hashed inputs across 12,288 registers.
Q23: What is the default eviction policy in Redis?
noeviction.
Q24: How does Spring @Cacheable work with Redis?
Uses Spring AOP to intercept method execution, querying Redis before executing the underlying Java logic[cite: 13].
Q25: What is Lettuce vs Jedis?
Jedis uses synchronous blocking I/O; Lettuce uses asynchronous non-blocking Netty channels and is thread-safe.
Q26: What is a QuickList?
A doubly-linked list of ZipLists, forming the underlying implementation of Redis Lists.
Q27: How does Redis execute expiration active scanning?
Runs 10 times a second, sampling 20 random keys with TTLs and purging expired ones.
Q28: What is the Cluster Bus?
A node-to-node binary TCP communication channel operating on port offset +10000 (e.g. 16379) for gossip protocol messaging.
Q29: How to protect Redis against unauthorized commands?
Rename or disable dangerous commands in redis.conf (e.g. rename-command FLUSHALL "") or use ACLs.
Q30: What is Pipelining?
Sending multiple commands sequentially to Redis without waiting for individual network ACKs.
Q31: What is the maximum memory setting in Redis?
Configured via the maxmemory directive.
Q32: How does Redis Pub/Sub differ from Redis Streams?
Pub/Sub is unpersisted fire-and-forget; Streams provides persistent append-only logs with consumer groups.
Q33: Can Redis be used as a primary database?
Yes, if configured with AOF persistence, proper replication, and sufficient RAM capacity.
Q34: What is SDS string encoding?
Simple Dynamic String encoding containing length prefix, free byte space, and raw character payload.
Q35: What is IntSet?
A compact binary encoding for Sets containing strictly integer values.
Q36: What is the purpose of HINCRBY?
Atomically increments an integer field value inside a Redis Hash.
Q37: What happens if a Master node fails in a Redis Cluster?
Replica nodes initiate election via gossip voting; a promoted replica assumes the master's hash slots.
Q38: What is the purpose of EXPIRE?
Sets a Time-To-Live timeout on a key in seconds.
Q39: What is PEXPIRE?
Sets a Time-To-Live timeout on a key in milliseconds.
Q40: How to monitor Redis performance live?
Using redis-cli stats, INFO command, or MONITOR.
Q41: What is ListPack?
The modern replacement for ZipList that eliminates cascading updates during payload alterations.
Q42: What is the purpose of SLOWLOG?
Logs commands exceeding specified execution time thresholds in memory.
Q43: What is Redis Sentinel Quorum?
The minimum number of Sentinel instances that must agree a master is unreachable before failover triggers.
Q44: Can Redis run on Windows in production?
No. Production Redis requires POSIX operating systems (Linux/BSD) for robust epoll/COW support.
Q45: What is the maximum number of keys per Redis instance?
Up to 2^32 keys (4.2 billion keys) per instance.
Q46: How does Redis support Geospatial indexes?
Encodes latitude and longitude pairs into 52-bit GeoHash integers stored inside Sorted Sets.
Q47: What is the purpose of XACK in Redis Streams?
Removes a processed message ID from the Pending Entries List (PEL) of a consumer group.
Q48: How to flush all keys in all databases?
FLUSHALL (or FLUSHALL ASYNC).
Q49: How to flush keys in the active database only?
FLUSHDB.
Q50: What is the difference between EMBSTR and RAW string encodings?
EMBSTR allocates the redisObject and SDS string payload in a single continuous memory block (<= 44 bytes); RAW uses separate allocations.
Q51: What is the AOF rewrite process?
Generates a minimal set of write commands representing the current dataset to shrink the AOF file size.
Q52: What is the purpose of CLIENT LIST?
Returns diagnostic information on all active connected client sockets.
Q53: How does Redis handle multi-key operations in Cluster mode?
Requires all keys in the command to belong to the exact same hash slot, enforced using hash tags {user:1001}.key.
Q54: What are Hash Tags?
Brackets inside a key name {...} that force Redis Cluster to compute the CRC16 hash slot on the bracketed text only.
Q55: What is the purpose of MGET?
Retrieves values for multiple string keys in a single atomic call.
Q56: What is the purpose of MSET?
Sets multiple key-value pairs in a single atomic call.
Q57: Does Redis support ACID transactions?
Redis supports Isolation and Durability (if configured with AOF), but lacks full Rollback support on runtime errors.
Q58: What is MEMORY USAGE key?
Returns the exact RAM byte footprint consumed by a specific key.
Q59: What is the default port of Redis?
6379.
Q60: What is the default port of Redis Sentinel?
26379.
Q61: What is the purpose of SINTER?
Computes the intersection of multiple input Sets.
Q62: What is the purpose of SUNION?
Computes the union of multiple input Sets.
Q63: What is the purpose of SDIFF?
Computes the difference between the first Set and subsequent Sets.
Q64: How does Spring Session Redis work?
Replaces HTTP Servlet Session state with a backing Redis Hash indexed by session ID.
Q65: What is the purpose of DUMP and RESTORE?
Serializes a key's value into an RDB-formatted byte payload and restores it back into a key.
Q66: How does Redis manage connection backlogs?
Configured via the tcp-backlog directive in redis.conf.
Q67: What is the purpose of PSYNC?
Used by replicas to request full or partial replication sync from a master.
Q68: What is a Lazy Free operation?
Reclaims memory in background threads via commands like UNLINK or FLUSHALL ASYNC.
Q69: What is the purpose of SETNX?
Sets a key value only if the key does not already exist (Set if Not eXists).
Q70: How to configure Redis as an LRU Cache?
Set maxmemory <bytes> and maxmemory-policy allkeys-lru in configuration.
Q71: What is the purpose of OBJECT ENCODING key?
Returns the internal low-level structural encoding used for a specific stored key.
Q72: What is the purpose of PERSIST key?
Removes the existing TTL timeout from a key, converting it to a permanent key.
Q73: How to trace all commands arriving at a Redis server live?
Execute MONITOR (use only for brief debugging due to performance impact).
Q74: What is Radix Tree (Rax)?
A memory-efficient space-optimized tree structure used by Redis to back Streams and Cluster slot routing.
Q75: What is the main architectural takeaway of Redis?
Sub-millisecond latency via in-memory execution, event-loop I/O multiplexing, and optimized specialized C structures.

32. Quick Revision Cheatsheet
