Spring Boot Startup Process — Complete Deep Dive

A beginner-friendly, simple, and complete guide to what happens behind the scenes when you boot a Spring Boot application—from main() and SpringApplication.run() to Auto-Configuration, Embedded Tomcat, and Application Events.

1. Introduction

When you click the "Run" button in your IDE or execute java -jar app.jar, a Spring Boot application starts up in a few seconds and prints a nice ASCII banner. But what actually happens in those few seconds?

Behind that simple boot screen, Spring Boot is performing dozens of automated setup tasks: scanning your code, setting up an in-memory application environment, configuring database connections, creating security filters, and starting a web server like Apache Tomcat.

Real-World Analogy: Opening a Restaurant

Running a Spring Boot application is like opening a restaurant for the day. Before customers can order food (HTTP requests), the manager must unlock the doors (JVM start), hire staff (Component Scan), organize ingredient suppliers (Auto Configuration), turn on the kitchen appliances (Embedded Tomcat), and announce the restaurant is open (ApplicationReadyEvent).

Why Understanding Startup Matters

Knowing the startup process helps you debug "BeanNotOfRequiredTypeException" or "Port already in use" errors, optimize slow application boot times, customize environment properties dynamically, and ace technical backend interviews.

High-Level Startup Overview

1
Java Main Execution: JVM calls your class's public static void main() method.
↓
2
Spring Boot Engine: SpringApplication.run() takes control to boot Spring.
↓
3
Environment & Container: Creates configuration environment and ApplicationContext container.
↓
4
Beans & Web Server: Creates Spring Beans, autowires dependencies, and starts Embedded Tomcat.
↓
5
Ready for Requests: Triggers ready listeners and waits for incoming HTTP traffic on port 8080.

3. main() Method

Every standard Java application requires a public static void main(String[] args) method as its entry point. Spring Boot applications follow this exact same standard Java rule.

package com.devvault;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class Application {

    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
What Happens Inside main()?
The main() method does not contain complex setup code. Instead, it acts as a launcher that passes two things to SpringApplication.run():
1. Application.class: Your primary configuration class (decorated with @SpringBootApplication).
2. args: Command-line arguments passed when executing the application (e.g., --server.port=9090).

4. SpringApplication.run()

SpringApplication.run() is the core engine function of Spring Boot. It delegates the complex bootstrapping workflow to a newly instantiated SpringApplication object.

What is SpringApplication?

A bootstrap helper class in package org.springframework.boot designed to create, configure, and refresh a Spring ApplicationContext from a simple Java main() method.

What Does run() Return?

It returns a fully initialized ConfigurableApplicationContext. This object holds all configured beans, environment properties, active profiles, and web server references.

5. SpringApplication Internals

When SpringApplication.run() is executed, it breaks down into two distinct phases:

Phase A: Object Instantiation (The Construction Phase)

When new SpringApplication(primarySources) is called, it initializes default settings:

  • 1. Detect Web Application Type: Checks the classpath. If DispatcherServlet and Servlet classes are present, it marks type as SERVLET. If Spring WebFlux is present, it marks type as REACTIVE. Otherwise, it sets NONE.
  • 2. Load Bootstrapper Initializers: Reads META-INF/spring.factories or org.springframework.boot.BootstrapRegistryInitializer from classpath JARs.
  • 3. Load Application Context Initializers: Finds classes implementing ApplicationContextInitializer.
  • 4. Load Application Listeners: Finds classes implementing ApplicationListener to process startup events.
  • 5. Deduce Main Application Class: Inspects the current thread call stack to identify the class containing the main() method.

Phase B: The run() Method Execution Phase

Next, the run(args) instance method executes the operational boot loop:

1
Starts a stopwatch to track startup metrics.
2
Prepares the ConfigurableEnvironment (reads application.properties and environment variables).
3
Prints the Spring Boot ASCII Banner to the log output.
4
Creates the appropriate ApplicationContext matching the web application type.
5
Refreshes the ApplicationContext (scans components, configures auto-configuration, creates beans, autowires dependencies, starts embedded Tomcat).
6
Executes all registered CommandLineRunner and ApplicationRunner beans.

6. Component Scanning

Component Scanning is the discovery process where Spring scans Java packages looking for classes annotated with stereotype annotations so it can manage them as Spring Beans.

Annotations Discovered During Scan
  • @Component: Generic Spring managed component.
  • @Service: Business logic layer component.
  • @Repository: Data access layer (DAO) component.
  • @RestController / @Controller: Web API controller component.
  • @Configuration: Java-based bean configuration class.
Default Package Scanning Rule

By default, @SpringBootApplication (via @ComponentScan) scans the package where your main application class resides, plus all sub-packages underneath it recursively.

Common Component Scan Bug:
If you place a controller or service in a package outside or parallel to the main application class package (e.g., main class in com.devvault.app and service in com.devvault.service), Spring Boot will NOT find it! It will fail to create the bean, resulting in "No qualifying bean of type found" at runtime.

7. Auto Configuration

Auto Configuration is Spring Boot's "magic" feature that automatically configures beans based on the JAR libraries present on your classpath.

Real-World Analogy: Smart Home System

Imagine a smart home system. If you plug in a TV, the home automatically detects it, configures the HDMI channels, and sets up the remote control. If you don't have a TV plugged in, it skips setting up TV channels. Auto Configuration works the exact same way with software dependencies!

How Spring Boot Decides What to Configure

If Spring Boot sees h2.jar on your classpath, it automatically creates an H2 in-memory DataSource bean. If it sees spring-boot-starter-web, it automatically configures an embedded Tomcat server and Jackson JSON converters.

Where Auto Configurations Live:
Spring Boot reads auto-configuration classes declared in imports files inside starter JARs located at:
META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports

8. Conditional Annotations

Auto Configuration relies heavily on Conditional Annotations. These annotations act as if-then checks that determine whether a configuration class or @Bean method should actually execute.

Conditional Annotation What It Checks (The Condition) Real-World Spring Boot Use Case
@ConditionalOnClass Checks if a specific .class exists on the JVM classpath. Configures Tomcat beans only if org.apache.catalina.Startup class exists on classpath.
@ConditionalOnMissingBean Checks if the developer has NOT already created a custom bean of this type. Configures default Jackson ObjectMapper only if you haven't defined your own custom ObjectMapper bean.
@ConditionalOnBean Checks if a specific bean already exists in the container. Configures a TransactionManager only if a DataSource bean has already been created.
@ConditionalOnProperty Checks if a configuration property in application.properties matches a value. Enables Swagger OpenAPI documentation beans only if app.swagger.enabled=true.
@ConditionalOnWebApplication Checks if the current application context is running as a web application. Configures web security filters and Spring MVC exception handlers only in web apps.
@ConditionalOnExpression Evaluates a complex Spring Expression Language (SpEL) boolean condition. Configures advanced caching beans based on complex multi-property checks.

9. Starter Dependencies

Before Spring Boot, developers had to manually search for, copy, and maintain compatible versions of dozens of third-party libraries in their pom.xml or build.gradle files.

Spring Boot Starters solved this problem by providing pre-packaged, curated sets of dependency descriptors. Adding a single starter brings in all required transitive dependencies with guaranteed version compatibility.

spring-boot-starter-web

Bundles Spring MVC, Embedded Tomcat, Jackson JSON serializer, and validation libraries needed to build REST APIs.

spring-boot-starter-data-jpa

Bundles Hibernate ORM, Spring Data JPA, Spring ORM, and JDBC connection pooling (HikariCP).

spring-boot-starter-security

Bundles Spring Security core, web security filters, BCrypt password encoders, and authentication mechanisms.

spring-boot-starter-test

Bundles JUnit 5, Mockito, AssertJ, Hamcrest, and Spring Test runner for unit and integration testing.

10. ApplicationContext Creation

The ApplicationContext is Spring's central Inversion of Control (IoC) container. It holds all managed objects (Beans), environment variables, active profiles, and event publishers.

BeanFactory vs ApplicationContext Hierarchy

1
BeanFactory (Interface): Low-level container interface that stores bean definitions and instantiates objects on request.
↓
2
ApplicationContext (Interface): High-level container extending BeanFactory; adds auto-configuration, AOP, events, i18n, and web server support.
↓
3
AnnotationConfigServletWebServerApplicationContext: Concrete class created by default for Spring Boot Web applications.

11. Bean Creation Process

Here is a simplified summary of how Spring Boot creates beans during startup:

1
Component Scan Discovery: Finds classes marked with @Component, @Service, etc.
2
BeanDefinition Registration: Registers class metadata (blueprints) into the BeanFactory registry.
3
Instantiation: Instantiates the raw Java object in heap memory using reflection or constructors.
4
Dependency Injection: Autowires dependent beans into constructors, setters, or fields.
5
Post-Processing & Ready: Runs @PostConstruct methods, wraps beans in AOP proxies if needed, and caches them.

12. Embedded Tomcat Server

In traditional Java EE development, you had to install an external application server (like standalone Apache Tomcat or WebLogic), build a .war file, and manually deploy it.

Spring Boot inverted this relationship: the web server is embedded inside your application .jar file! Your application owns the web server, not the other way around.

Feature Traditional WAR Deployment Spring Boot Embedded Tomcat
Server Installation Must manually install and configure external Tomcat server on OS. Zero installation required! Embedded server JAR comes bundled inside application.
Execution Method Build .war file → Copy to Tomcat /webapps folder. Build executable .jar file → Run java -jar app.jar.
Configuration & Port Configured via Tomcat's server.xml file. Configured simply via server.port=8080 in application.properties.
Cloud & Docker Friendly Harder to containerize and scale. Extremely easy to package into Docker containers and deploy to Kubernetes.

14. Application Startup Events

Spring Boot fires a series of lifecycle events during startup. You can attach custom ApplicationListener beans to hook into any stage of startup.

Startup Event Sequence Timeline

1
ApplicationStartingEvent: Fired right at the beginning before environment or context creation.
2
ApplicationEnvironmentPreparedEvent: Fired when environment properties (application.properties) are ready.
3
ApplicationContextInitializedEvent: Fired when ApplicationContext is created but before beans are loaded.
4
ApplicationPreparedEvent: Fired when bean definitions are loaded but singletons are not instantiated yet.
5
ApplicationStartedEvent: Fired when context is refreshed and beans are ready, but runners have not executed.
6
ApplicationReadyEvent: Fired when the app is completely ready to handle incoming network traffic.
7
ApplicationFailedEvent: Fired if an unhandled exception occurs at any point during startup.

15. CommandLineRunner & ApplicationRunner

If you need to run specific custom code right after the application finishes starting up (such as seeding initial database data or warming up caches), Spring Boot provides two runner interfaces.

@Component
public class DatabaseSeeder implements CommandLineRunner {

    @Override
    public void run(String... args) throws Exception {
        System.out.println("Executing database seed scripts at startup...");
    }
}
Runner Interface Method Signature Argument Passing Format
CommandLineRunner run(String... args) Passes raw command line arguments as a plain array of Strings.
ApplicationRunner run(ApplicationArguments args) Passes parsed ApplicationArguments object providing methods to query option and non-option args.

16. Production Startup Flow

Here is what happens in a production REST API when you execute java -jar app.jar:

Production Executable JAR Launch Sequence

1. Operating System starts JVM process → Reads manifest file META-INF/MANIFEST.MF inside JAR.

↓

2. Executes JarLauncher → Unpacks nested BOOT-INF/classes and BOOT-INF/lib dependencies.

↓

3. Calls Application.main(args) → Invokes SpringApplication.run().

↓

4. Evaluates Auto-Configuration & Component Scan → Instantiates HikariCP DataSource pool & JPA Repositories.

↓

5. Starts Embedded Tomcat on Port 8080 → Registers DispatcherServlet & Spring Security Filters.

↓

6. Fires ApplicationReadyEvent → Logs "Started Application in 2.45 seconds" → Listens for HTTP traffic.

17. Common Startup Mistakes

1. Wrong Package Hierarchy: Placing your main class inside a sub-package causes Component Scanning to miss your controllers and services located in parallel packages.

2. Port 8080 Already in Use: Trying to start an app when port 8080 is occupied by another process. Fix by adding server.port=9090 in application.properties.

3. Circular Dependencies During Startup: Service A requires Service B, while Service B requires Service A. Fix by using @Lazy or refactoring design.

4. Missing Database Driver: Including spring-boot-starter-data-jpa without providing a database driver JAR (like PostgreSQL or MySQL driver) causes immediate DataSource creation failure.

18. Senior Best Practices

  • Keep Main Package Top-Level: Place your @SpringBootApplication class in a root package like com.company.project so Component Scan discovers all sub-packages automatically.
  • Avoid Heavy Work in Constructors / Runners: Do not run blocking network calls or slow operations on the main startup thread.
  • Use Constructor Injection: Mark dependencies private final and inject them via constructors to catch missing beans at startup.
  • Enable Lazy Initialization for Development: Set spring.main.lazy-initialization=true in dev environments to drastically speed up boot times.

19. 40+ Interview Questions

Q1: What happens inside SpringApplication.run()?
It creates a SpringApplication instance, sets environment properties, instantiates the appropriate ApplicationContext matching web type (Servlet/Reactive), loads auto-configurations, performs component scanning, creates and autowires singleton beans, starts embedded Tomcat server, executes runners, and fires ApplicationReadyEvent.
Q2: What is Auto Configuration in Spring Boot?
A Spring Boot mechanism that automatically configures and creates beans based on the JAR libraries detected on your classpath and configuration properties, using conditional annotations.
Q3: What is the difference between SpringApplication and ApplicationContext?
SpringApplication is the bootstrap engine class used to configure and start the app. ApplicationContext is the actual IoC container holding all managed beans, environment properties, and events.
Q4: How does Component Scan work in Spring Boot?
It scans the package containing the @SpringBootApplication class and all its sub-packages, registering classes annotated with @Component, @Service, @Repository, @RestController, and @Configuration as managed beans.
Q5: What is Embedded Tomcat and why is it useful?
It is a web server bundled directly inside your executable JAR application file. It eliminates the need to manually install, configure, and deploy WAR files to external application servers.
Q6: What is @SpringBootApplication composed of?
It is a meta-annotation composed of @SpringBootConfiguration, @EnableAutoConfiguration, and @ComponentScan.
Q7: What is @ConditionalOnClass?
A conditional annotation that enables configuration only if a specific class is present on the JVM classpath.
Q8: What is @ConditionalOnMissingBean?
A conditional annotation that creates a default bean only if the developer has not already created a custom bean of that type.
Q9: What is the purpose of CommandLineRunner?
An interface used to execute custom initialization code after the ApplicationContext has booted and singletons are ready.
Q10: Difference between CommandLineRunner and ApplicationRunner?
CommandLineRunner passes raw String[] args; ApplicationRunner passes parsed ApplicationArguments object.
Q11: Where does Spring Boot store auto-configuration import lists?
In META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports inside starter JARs.
Q12: How to change embedded server port in Spring Boot?
By setting server.port=9090 in application.properties.
Q13: How to disable a specific auto-configuration class?
By using @SpringBootApplication(exclude = {DataSourceAutoConfiguration.class}).
Q14: How does Spring Boot determine if an app is web-based?
By inspecting the classpath for web classes like DispatcherServlet or WebFlux.
Q15: What is the Condition Evaluation Report?
A diagnostic log generated when running with --debug showing positive and negative auto-configuration matches.
Q16: What event is fired when Spring Boot finishes booting?
ApplicationReadyEvent.
Q17: What event is fired if Spring Boot fails during startup?
ApplicationFailedEvent.
Q18: What are Spring Boot Starter dependencies?
Curated sets of dependency descriptors that aggregate compatible library versions into single convenient POM imports.
Q19: How to run custom code right before context creation?
By attaching an ApplicationListener listening for ApplicationStartingEvent.
Q20: Why should main class be in root package?
So default @ComponentScan scans all application packages and sub-packages without missing beans.
Q21: What is spring-boot-starter-web?
A starter bundling Spring MVC, Embedded Tomcat, and Jackson JSON dependencies for REST API creation.
Q22: How to switch embedded Tomcat to Jetty?
Exclude spring-boot-starter-tomcat from web starter and add spring-boot-starter-jetty.
Q23: How to speed up Spring Boot startup in development?
Set spring.main.lazy-initialization=true in application.properties.
Q24: What is @ConditionalOnProperty?
Loads configuration conditionally based on a property value in application.properties.
Q25: What is JarLauncher in Spring Boot?
An internal Spring Boot loader that executes executable JARs by loading nested BOOT-INF classes.
Q26: What is @EnableAutoConfiguration?
Annotation enabling Spring Boot's auto-configuration mechanism.
Q27: What is Spring Boot Banner?
The ASCII art banner printed in console during startup, customizable via banner.txt.
Q28: What is ApplicationContextInitializer?
Callback interface for initializing Spring ApplicationContext prior to bean refresh.
Q29: How to pass arguments to Spring Boot executable JAR?
Using java -jar app.jar --server.port=9090 --spring.profiles.active=prod.
Q30: What is spring.factories?
Legacy SPI configuration file inside META-INF used to declare initializers, listeners, and auto-configurations.
Q31: What happens if port 8080 is in use?
Tomcat fails to bind to port and application throws PortInUseException during startup.
Q32: How to turn off Spring Boot Banner?
Set spring.main.banner-mode=off in application.properties.
Q33: How does Spring Boot handle multiple runners?
Executes them in sequence; order can be controlled using @Order annotation.
Q34: What is Spring Application Environment?
Object representing active profiles, OS environment variables, system properties, and application.properties.
Q35: Can Spring Boot run without an embedded web server?
Yes! Non-web applications (e.g., CLI batch jobs) set WebApplicationType to NONE.
Q36: What is @SpringBootConfiguration?
A specialization of @Configuration used by Spring Boot to mark primary configuration classes.
Q37: Difference between @ComponentScan and Auto-Configuration?
@ComponentScan scans your project classes; Auto-Configuration evaluates starter libraries on classpath.
Q38: How to print startup metrics in Spring Boot 3?
Spring Boot logs total startup elapsed time in seconds upon ApplicationReadyEvent.
Q39: What is Spring Boot AOT startup?
Ahead-of-Time compilation in Spring Boot 3 pre-calculates bean definitions at build time for instant boot.
Q40: What is the main benefit of understanding Spring Boot startup?
Helps debug startup failures, optimize boot performance, customize configuration, and master Spring architecture.

20. Revision Cheatsheet

main(): Standard Java entry point calling SpringApplication.run().
