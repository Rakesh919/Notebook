1. Introduction to Annotations

Java annotations (introduced in Java 5 via JSR-175) are structured metadata tags embedded directly into Java source code. They do not alter compiled bytecode directly; instead, they provide metadata that can be inspected by tools, compilers, or runtime frameworks using reflection.

Why Spring Replaced XML with Annotations

Early Spring (1.x/2.0) relied on massive XML configuration files (applicationContext.xml). As enterprise applications grew, XML configurations caused extreme refactoring pain, lack of type safety, and configuration sprawl. Annotations co-locate configuration directly with the target code.

How Spring Processes Annotations

Spring uses ClassPathBeanDefinitionScanner and high-performance ASM bytecode parsers (MetadataReader) to detect annotations without loading classes into the JVM ClassLoader initially. At runtime, BeanPostProcessors inspect annotations using Java Reflection to inject dependencies, wrap beans in AOP proxies, or configure web endpoints.

4. Spring Framework (Core) Annotations

Package: org.springframework.context.annotation & org.springframework.beans.factory.annotation

@Component / @Service / @Repository / @Controller

Stereotype annotations derived from @Component. Scanned automatically during classpath scanning. @Repository enables SQL exception translation, and @Service defines business layer pointcuts.

@Configuration & @Bean

Defines factory methods returning beans. @Configuration classes are enhanced via CGLIB proxies to enforce singleton guarantees for inter-bean method calls.

@Autowired / @Qualifier / @Primary

@Autowired injects dependencies by type. @Primary sets a default fallback candidate. @Qualifier targets a specific bean by name.

@Value & @PropertySource

Injects property values from application.properties using SpEL expressions (e.g. @Value("${app.timeout}")).

@Scope & @Lazy

@Scope sets lifecycle scopes (singleton, prototype, request, session). @Lazy defers initialization until first request.

@PostConstruct & @PreDestroy

Standard JSR-250 lifecycle hooks executed after dependency injection and before bean destruction.

        SpringApplication.run(Application.class, args);
    }
}

// Conditional Auto-Configuration Bean
@Bean
@ConditionalOnMissingBean(PaymentService.class)
@ConditionalOnProperty(name = "feature.payment.enabled", havingValue = "true")

    return new DefaultPaymentServiceImpl();
}

6. Spring MVC Annotations

Package: org.springframework.web.bind.annotation

Spring MVC Request Handling Flow

HTTP Request → DispatcherServlet → HandlerMapping (scans @RestController / @GetMapping) → Controller Handler Execution → HttpMessageConverter (translates object via Jackson) → HTTP Response

@RestController
@RequestMapping("/api/v1/orders")
@CrossOrigin(origins = "https://devvault.com")
public class OrderController {

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public OrderResponse createOrder(
            @Valid @RequestBody OrderRequest request,
            @RequestHeader("X-Correlation-ID") String correlationId) {
        return orderService.process(request, correlationId);
    }

    @GetMapping("/{id}")
    public OrderResponse getOrder(@PathVariable("id") Long orderId) {
        return orderService.findById(orderId);
    }
}

7. Spring Data JPA Annotations

Packages: jakarta.persistence & org.springframework.transaction.annotation

@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "email", nullable = false, unique = true)
    private String email;

    @Version // Optimistic Locking
    private Integer version;

    @OneToMany(mappedBy = "user", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    private List<Order> orders = new ArrayList<>();
}
@Transactional Pitfall: @Transactional uses Spring AOP proxies. Calling a @Transactional method from within the same class (self-invocation) bypasses the proxy, disabling transaction management.

10. Spring AOP Annotations

Package: org.aspectj.lang.annotation

@Aspect
@Component
public class LoggingAspect {

    @Pointcut("execution(* com.devvault.service..*.*(..))")
    public void serviceLayer() {}

    @Around("serviceLayer()")
    public Object profileExecution(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = joinPoint.proceed();
        long elapsed = System.currentTimeMillis() - start;
        logger.info("Executed {} in {} ms", joinPoint.getSignature(), elapsed);
        return result;
    }
}

18. Common Production Mistakes

1. Field Injection using @Autowired: Hides dependencies and prevents immutability. Use Constructor Injection.
2. Self-Invocation of @Transactional or @Async methods: Bypasses Spring's CGLIB proxy, rendering the annotations non-functional.
3. Catching Exception inside @Transactional without rethrowing: Prevents Spring from detecting transaction failure and rolling back changes.

19. Senior Best Practices

  • Always use constructor injection for required dependencies and mark fields private final.
  • Prefer @ConfigurationProperties with typed POJOs over scatter-shot @Value properties.
  • Place global exception handling in @RestControllerAdvice classes rather than try-catch blocks in controllers.

20. 100 Spring Interview QA

Q1: What is @SpringBootApplication composed of?
Composed of @SpringBootConfiguration, @EnableAutoConfiguration, and @ComponentScan.
Q2: How does @Autowired resolve dependencies?
Matches candidate beans by exact type first, then uses @Qualifier, @Primary, or field parameter name as fallback.
Q3: Difference between @Component, @Service, and @Repository?
All are component stereotypes. @Repository enables SQL exception translation; @Service designates business layer pointcuts.
Q4: Why are @Configuration classes proxied with CGLIB?
To intercept inter-bean method calls and return the existing singleton instance from the BeanFactory.
Q5: Difference between @Controller and @RestController?
@RestController meta-annotates @Controller and @ResponseBody, automatically serializing response objects to JSON/XML.
Q6: What is @PathVariable vs @RequestParam?
@PathVariable extracts values from URI path segments (/users/{id}). @RequestParam extracts query parameters (/users?id=1).
Q7: What is the purpose of @Transactional(readOnly = true)?
Optimizes database session management by disabling dirty checking and flushing on Hibernate sessions.
Q8: How does @PreAuthorize work?
Uses Spring Security AOP proxies to evaluate SpEL expressions before executing the target method.
Q9: Difference between @NotNull, @NotEmpty, and @NotBlank?
@NotNull prevents null. @NotEmpty prevents null and empty length. @NotBlank prevents null, empty, or whitespace-only strings.
Q10: What is @MockBean used for?
Replaces a bean in the Spring ApplicationContext with a Mockito mock during integration testing.
Q11: What is @ConditionalOnMissingBean?
Registers a bean only if no bean of the same type exists in the BeanFactory.
Q12: What is @ConfigurationProperties?
Binds hierarchical external properties from application.properties to a strongly-typed Java POJO.
Q13: How does @Cacheable work?
Intercepts method call, checks configured cache manager by key; returns cached value if hit, runs method on miss.
Q14: What is @Version used for in JPA?
Enables optimistic locking by tracking entity modification version numbers.
Q15: Difference between @Bean and @Component?
@Component is class-level for automatic scanning; @Bean is method-level inside @Configuration for third-party objects.
Q16: What is @RestControllerAdvice?
Combines @ControllerAdvice and @ResponseBody for centralized REST exception handling.
Q17: What is @Scheduled(cron = "... ")?
Schedules method execution using a 6-field cron expression.
Q18: What is @Async?
Executes marked methods asynchronously in a separate task thread pool.
Q19: What is @Primary?
Designates a primary candidate bean when multiple beans match an injection point.
Q20: What is @Qualifier?
Specifies the exact bean name identifier to inject when multiple candidates exist.
Q21: What is @Value?
Injects property values or SpEL results into bean fields or parameters.
Q22: What is @Lazy?
Defers bean instantiation until explicit runtime access.
Q23: What is @Scope("prototype")?
Creates a new instance every time the bean is requested from the container.
Q24: What is @PostConstruct?
Lifecycle hook invoked after property injection completes.
Q25: What is @PreDestroy?
Lifecycle hook invoked before bean destruction.
Q26: What is @EnableAutoConfiguration?
Enables Spring Boot auto-configuration based on classpath dependencies.
Q27: What is @ComponentScan?
Directs Spring to scan specified packages for stereotype components.
Q28: What is @Entity?
Marks a Java class as a JPA persistent domain entity.
Q29: What is @Table?
Specifies the target database table name and constraints for an entity.
Q30: What is @Id?
Designates the primary key field of a JPA entity.
Q31: What is @GeneratedValue?
Configures primary key generation strategies (IDENTITY, SEQUENCE, AUTO, TABLE).
Q32: What is @Column?
Configures database column mappings, names, nullability, and lengths.
Q33: What is @Transient?
Instructs JPA to ignore a field during database persistence.
Q34: What is @OneToMany?
Defines a one-to-many entity relationship mapping.
Q35: What is @ManyToOne?
Defines a many-to-one entity relationship mapping.
Q36: What is @JoinColumn?

Q96: What is @Target(ElementType.TYPE)?

Q97: Difference between @DataJpaTest and @SpringBootTest?
@SpringBootTest loads full context; @DataJpaTest slices context to test JPA repositories only.
Q98: What is @OneToOne?
Defines a one-to-one entity relationship mapping.
Q99: How does Spring resolve @Value placeholders?
Uses PropertySourcesPlaceholderConfigurer to inspect active Environment property sources.

To enforce declarative programming, co-locate configuration metadata with code, and eliminate XML boilerplate.
