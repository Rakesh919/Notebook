The IoC Container

What it is, why Spring built the whole framework around it, and how it decides what gets created and when.

The core idea

Normally, your code creates the objects it needs with new. With Inversion of Control, that responsibility flips: a container creates the objects, wires them together, and hands them to you. You stop controlling object creation — the container does.

Analogy: think of a restaurant kitchen. You don't walk in and cook your own food — you place an order, and the kitchen (the container) prepares it and brings it to you fully assembled.

BeanFactory vs ApplicationContext

BeanFactory is the basic container: lazy, minimal, rarely used directly today. ApplicationContext builds on it — eager initialization by default, event handling, internationalization, and integration with annotations like @Component and @Autowired. In a real Spring Boot app, you're always working with an ApplicationContext.

@Component
class OrderService {
    // Spring creates this and manages its lifecycle
}

Why it matters for interviews

This is usually the first "explain it like I'm five, then explain it for real" question in a Spring interview. Interviewers want to hear both the plain-language version and the precise one — container, bean definition, bean instantiation, dependency resolution.
