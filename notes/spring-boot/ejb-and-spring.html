EJB vs Spring vs Spring Boot vs Spring MVC

What each one actually is, what problem it was built to solve, what's bundled inside it, and how they relate — not competitors, but layers built on top of one another.

1. What Is EJB?

EJB (Enterprise JavaBeans) is the original Java EE specification for building server-side, transactional, distributed business components. Every EJB class had to implement container-mandated interfaces and be declared in verbose XML deployment descriptors (ejb-jar.xml). It could only run inside a full Java EE application server — GlassFish, WebLogic, JBoss — there was no lightweight or standalone option.

Session Beans

Encapsulated business logic. Stateless beans handled request-scoped logic; stateful beans held conversational state per client.

Entity Beans

Represented persistent data (pre-JPA). Heavy, container-managed persistence that was eventually replaced by JPA.

Message-Driven Beans

Consumed messages from JMS queues/topics asynchronously, managed entirely by the container.

Container Services

Transactions, security, and remoting were declared via annotations/XML and enforced by the app server — powerful, but rigid and slow to develop against.

EJB's core problem wasn't its ideas (transactions, pooling, remoting are all still valuable) — it was the cost of using them: mandatory interfaces, a full app server, and slow edit-deploy-test cycles.

2. What Is the Spring Framework?

Spring emerged in 2003 as a direct reaction to EJB's complexity. Its core idea: business logic should be plain Java objects (POJOs) with no forced interfaces, and the framework should wire dependencies together rather than components looking them up themselves.

IoC Container

The heart of Spring. Creates, configures, and manages the lifecycle of objects ("beans") so your code doesn't have to.

Dependency Injection

Dependencies are supplied to a class (via constructor/setter) instead of the class creating or looking them up itself — enabling easy testing and loose coupling.

Spring AOP

Aspect-Oriented Programming — cross-cutting concerns (logging, transactions, security) applied declaratively without cluttering business code.

Spring Data / ORM Support

Abstractions over JDBC, JPA/Hibernate that cut down boilerplate for data access.

Spring Security

Configurable authentication and authorization — a full replacement for EJB's container-managed security.

Spring MVC

Spring's own web framework, covered in detail below.

What Spring didn't fix: you still had to hand-configure most of it — XML bean definitions (later @Configuration Java config), manually chosen dependency versions, and manual deployment to an external servlet container as a .war.

3. What Is Spring Boot?

Spring Boot (2014) doesn't replace Spring — it's built directly on top of it. Its entire purpose is removing the configuration burden that remained after Spring solved EJB's complexity problem: "convention over configuration," sensible defaults, and a runnable standalone application.

1. Auto-Configuration

Scans classpath jars and conditionally creates beans using annotations like @ConditionalOnClass and @ConditionalOnMissingBean — if it sees a JPA driver, it wires up a DataSource for you.

2. Starters Ecosystem

Single dependency wrappers (e.g., spring-boot-starter-data-jpa) bundling compatible versions of Hibernate, Spring Data, and JDBC — no manual version matching.

3. Embedded Web Containers

Executes applications standalone via public static void main using a built-in Tomcat/Jetty/Undertow — a runnable .jar, not a .war deployed externally.

4. Spring Boot Actuator

Provides production-ready REST endpoints (/actuator/health, /actuator/metrics, /actuator/env) without writing any business code.

5. Externalized Configuration

application.properties/application.yml with profile-based overrides (application-dev.yml) baked in.

6. Opinionated Defaults

Sensible out-of-the-box choices (embedded Tomcat, Jackson for JSON, logback for logging) that you can override, but don't have to configure.

4. What Is Spring MVC?

Spring MVC is the web framework layer inside the Spring ecosystem — it existed in Spring Core long before Spring Boot did. It is not a competitor to Spring Boot; Spring Boot simply auto-configures Spring MVC the moment you add spring-boot-starter-web to your classpath.

At its center is the DispatcherServlet — a front controller that receives every incoming HTTP request, routes it to the right controller method based on URL/HTTP verb, and delegates response rendering. Around that core, Spring MVC provides a large set of annotations that let you declare routing, request binding, and validation instead of writing servlet plumbing by hand.

Core Spring MVC Annotations

AnnotationWhat It Does
@ControllerMarks a class as a web controller whose methods return view names (for server-rendered pages).
@RestControllerShorthand for @Controller + @ResponseBody — every method's return value is serialized directly into the HTTP response body (typically JSON), the default for REST APIs.
@RequestMappingMaps a class or method to a URL path; base annotation behind the verb-specific shortcuts below.
@GetMapping / @PostMapping / @PutMapping / @DeleteMapping / @PatchMappingVerb-specific shortcuts for @RequestMapping(method = ...).
@ResponseBodyTells Spring to write the method's return value straight into the HTTP response body instead of resolving it as a view name.
@RequestBodyDeserializes the incoming HTTP request body (usually JSON) into a Java object parameter.
@PathVariableBinds a URI template segment (e.g., /users/{id}) to a method parameter.
@RequestParamBinds a query string parameter (e.g., ?page=2) to a method parameter.
@RequestHeaderBinds an HTTP header value to a method parameter.
@ValidTriggers bean validation (JSR-380) on the annotated object — combined with constraint annotations like @NotNull, @Size, @Email on the DTO fields.
@ExceptionHandlerMarks a method to handle exceptions thrown by controller methods in the same class.
@ControllerAdvice / @RestControllerAdviceApplies exception handling, binding, or model attributes globally across all controllers.
@ResponseStatusSets a specific HTTP status code on the response for a given handler or exception.
@CrossOriginEnables CORS for a controller or handler method.

Spring Boot's Own Bootstrapping Annotation

One annotation often confused as part of Spring MVC is actually Spring Boot's entry point:

@SpringBootApplication

A convenience annotation combining three: @Configuration (marks the class as a source of bean definitions), @EnableAutoConfiguration (turns on Spring Boot's classpath-based auto-configuration), and @ComponentScan (scans the package for @Component/@Service/@Repository/@Controller beans). It's placed once, on the class containing public static void main.

@SpringBootApplication
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}

@RestController
@RequestMapping("/api/products")
@RequiredArgsConstructor
public class ProductController {

    private final ProductService productService;

    @GetMapping("/{id}")
    public ResponseEntity<ProductResponse> getProduct(@PathVariable Long id) {
        return ResponseEntity.ok(productService.getProduct(id));
    }

    @PostMapping
    public ResponseEntity<ProductResponse> createProduct(@Valid @RequestBody ProductRequest request) {
        ProductResponse created = productService.create(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(created);
    }

    @ExceptionHandler(ProductNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ErrorResponse handleNotFound(ProductNotFoundException ex) {
        return new ErrorResponse(ex.getMessage());
    }
}

5. Spring Core vs. Spring Boot

Spring Core provides the underlying Dependency Injection framework and low-level abstractions. Spring Boot sits on top of Spring to remove boilerplate and manual setup.

Feature Spring Framework (Core + MVC) Spring Boot
Configuration Strategy Explicit manual config via XML files or Java @Configuration beans. Auto-Configuration based on classpath starters and conditions.
Server Deployment Requires building a .war file and deploying to an external Tomcat/WildFly. Includes an Embedded Server (Tomcat, Jetty, Undertow) inside a runnable .jar.
Dependency Management Manual tracking of compatible versions across dozens of Spring jars. Starter POMs (e.g., spring-boot-starter-web) with curated transitive versions.
Production Readiness Requires custom setup for metrics, health checks, and tracing. Includes Spring Boot Actuator out-of-the-box for production monitoring.

7. The Relationship, Summed Up

EJB → Spring → Spring Boot is a lineage, not a set of competitors. Spring was built to remove EJB's mandatory complexity. Spring Boot was built to remove the manual configuration that was still left over in Spring. Spring MVC is not a rival to any of them — it's the web layer that has lived inside Spring since the beginning, and Spring Boot simply auto-configures it for you.
