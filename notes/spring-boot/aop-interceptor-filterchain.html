Spring AOP vs Filters vs Interceptors — Complete Deep Dive

The definitive guide to understanding interception layers in Java web applications: Servlet Filters, Spring MVC Interceptors, and Aspect-Oriented Programming (AOP), their internal working, execution order, trade-offs, and production design patterns.

1. Introduction & Why Three Exist

When building enterprise web applications, you frequently need to execute code before or after core business logic—tasks such as checking security tokens, logging request execution time, managing database transactions, or handling CORS headers. These are called Cross-Cutting Concerns.

Spring and the Java Servlet Specification provide three distinct mechanisms for intercepting execution: Servlet Filters, Spring MVC Interceptors, and Spring AOP (Aspects). Beginners often ask: "Why do we need three different ways to intercept execution? Can't one replace the others?"

Real-World Analogy: Airport Security Layers

• Servlet Filter (Airport Main Gate Security): Inspects everyone entering the airport grounds. It doesn't care which flight you take; it checks raw physical security, passport validity, and baggage size before you enter the terminal.

• Spring Interceptor (Flight Boarding Gate Counter): Inspects passengers boarding a specific flight. It knows about airline routes, ticket seats, and passenger classes (Spring Controllers & Endpoints).

• Spring AOP (In-Flight Personal Service / Pilot Instructions): Applies specific rules around individual passenger interactions or cockpit operations (Service & Repository methods) regardless of HTTP or web context.

Why One Cannot Replace the Others

Each mechanism operates at a completely different architectural layer with different access levels to HTTP objects, Spring context, and target method signatures. For instance, a Filter can wrap raw HTTP streams (CORS/GZIP) before Spring even runs, an Interceptor understands Spring MVC handler mappings, and AOP can wrap any method call anywhere in the application (even background CLI jobs or message listeners) without an HTTP request!

3. Servlet Filter Overview

A Servlet Filter is an object defined by the Jakarta Servlet Specification (jakarta.servlet.Filter). It operates at the low-level web container tier (Tomcat, Jetty, Undertow) outside of Spring MVC's DispatcherServlet.

Key Responsibilities
  • Inspecting, modifying, or blocking raw HttpServletRequest and HttpServletResponse objects.
  • Wrapping request/response streams (e.g. ContentCachingRequestWrapper for body re-reading).
  • Executing low-level web protocols: CORS headers, GZIP compression, character encoding.
  • Enforcing baseline container security filters (Spring Security's DelegatingFilterProxy).

4. Spring Interceptor Overview

A HandlerInterceptor is a Spring MVC framework component (org.springframework.web.servlet.HandlerInterceptor). It intercepts HTTP requests inside the DispatcherServlet, right before and after they reach Spring MVC Controllers.

Key Responsibilities
  • Intercepting requests with full awareness of the target Spring HandlerMethod (Controller method signature).
  • Extracting execution timing metrics specific to web endpoints.
  • Inspecting or attaching model attributes for template rendering.
  • Executing pre-controller security or tenant resolution logic.

5. Spring AOP Overview

Spring AOP (Aspect-Oriented Programming) is a core Spring framework feature (org.springframework.aop) that uses dynamic proxies (JDK or CGLIB) to wrap method executions around Spring-managed beans across any architectural layer (Service, Repository, Custom Component).

Key Responsibilities
  • Interception of method calls anywhere in the application (completely independent of HTTP/Web context).
  • Managing declarative transactions via @Transactional.
  • Declarative caching operations via @Cacheable and @CacheEvict.
  • Method performance monitoring, retry logic, and fine-grained auditing.

8. Filter Deep Dive

Filters are declared in standard Servlet specifications. Spring Boot provides OncePerRequestFilter to guarantee a filter executes strictly once per request dispatch (avoiding duplicate runs during internal forwards/includes).

@Component
public class CorrelationIdFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        
        String correlationId = req.getHeader("X-Correlation-ID");
        if (correlationId == null || correlationId.isBlank()) {
            correlationId = UUID.randomUUID().toString();
        }
        
        // Attach to logging MDC context and response headers
        MDC.put("correlationId", correlationId);
        res.setHeader("X-Correlation-ID", correlationId);

        try {
            chain.doFilter(req, res); // Pass request to next filter / DispatcherServlet
        } finally {
            MDC.remove("correlationId"); // Clean up thread-local MDC
        }
    }
}

9. Interceptor Deep Dive

An Interceptor implements HandlerInterceptor and is registered via WebMvcConfigurer. It gives you direct access to the target Spring HandlerMethod object.

@Component
public class RequestTimingInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) {
        long startTime = System.currentTimeMillis();
        req.setAttribute("startTime", startTime);
        return true; // true = continue execution; false = block request here
    }

    @Override
    public void afterCompletion(HttpServletRequest req, HttpServletResponse res, Object handler, Exception ex) {
        long startTime = (Long) req.getAttribute("startTime");
        long duration = System.currentTimeMillis() - startTime;
        
        if (handler instanceof HandlerMethod) {
            HandlerMethod hm = (HandlerMethod) handler;
            System.out.println(hm.getShortLogMessage() + " executed in " + duration + "ms");
        }
    }
}

10. AOP Deep Dive

Spring AOP uses dynamic proxies (JDK Dynamic Proxy or CGLIB) to wrap target Spring Beans and execute advice around method join points based on Pointcut expressions.

@Aspect
@Component
public class ServiceAuditAspect {

    @Around("execution(* com.devvault.service..*.*(..))")
    public Object auditMethod(ProceedingJoinPoint joinPoint) throws Throwable {
        System.out.println("AOP BEFORE: Executing " + joinPoint.getSignature());
        
        Object result = joinPoint.proceed(); // Call real method
        
        System.out.println("AOP AFTER: Completed " + joinPoint.getSignature());
        return result;
    }
}

12. Decision Guide: When to Use Which?

Use Servlet Filter For:
  • Raw request/response body wrapping (e.g. logging JSON payloads multiple times).
  • CORS headers and GZIP response compression.
  • Global web security filter chains (Spring Security).
  • Character encoding and low-level IP rate limiting.
Use Spring Interceptor For:
  • JWT token validation specific to web controllers.
  • Extracting execution metrics per Controller endpoint.
  • Attaching user/tenant context to Spring MVC requests.
  • Handling locale or theme changes in web apps.
Use Spring AOP For:
  • Declarative transaction management (@Transactional).
  • Declarative caching (@Cacheable).
  • Method performance monitoring across Service/Repository layers.
  • Custom annotation interception (e.g. @AuditLog).

14. Internal Working & Classes

  • ApplicationFilterChain: Tomcat internal class executing registered Filter chains sequentially.
  • DispatcherServlet: Spring MVC front controller executing HandlerExecutionChain.
  • HandlerExecutionChain: Holds the controller handler and the list of HandlerInterceptor objects.
  • AnnotationAwareAspectJAutoProxyCreator: Internal Spring BeanPostProcessor that wraps Spring Beans in CGLIB/JDK dynamic proxies for AOP aspects.

16. Common Architectural Mistakes

1. Using AOP for Request Body Logging: Trying to read HttpServletRequest.getInputStream() inside an AOP aspect on a Service method. The stream can only be read ONCE by default! Body wrapping must happen at the Servlet Filter layer using ContentCachingRequestWrapper.

2. Using Interceptors for Non-Web Business Logic: Placing business rule validation inside an Interceptor means those rules won't run when called from a background Kafka consumer or CLI runner.

3. Self-Invocation Trap in AOP: Calling an @Transactional or custom aspect method from within the same class bypasses the Spring AOP Proxy wrapper completely!

17. Senior Best Practices

  • Extend OncePerRequestFilter for custom Filters to prevent duplicate executions during internal request dispatches.
  • Clean up ThreadLocal variables (such as MDC or SecurityContext) inside finally blocks in Filters or afterCompletion() in Interceptors to prevent memory leaks in Tomcat thread pools.
  • Use explicit @Order annotations on Filters and Aspects to guarantee deterministic execution order.

19. 60+ Senior Interview Questions

Q1: What is the main difference between a Filter, an Interceptor, and AOP?
Filters belong to the Servlet container and intercept raw HTTP requests/responses outside Spring MVC. Interceptors belong to Spring MVC and intercept requests around Controller endpoints. AOP belongs to Spring Core and intercepts method calls on any Spring Bean using dynamic proxies.
Q2: Which component executes first when an HTTP request arrives?
The Servlet Filter executes first, before the DispatcherServlet or Interceptors are invoked.
Q3: Can an Interceptor modify the raw HttpServletRequest InputStream body?
No. The InputStream stream can only be read once. To wrap or cache the request body stream, you must use a Servlet Filter with a request wrapper class.
Q4: Why does Spring Security use Filters instead of Interceptors or AOP?
Because security checks (CORS, CSRF, authentication headers) must run at the earliest entry point before any web parsing or controller mapping occurs, and must protect all web endpoints (including static assets).
Q5: Why are Spring Transactions (@Transactional) implemented using AOP?
Because transactions are a business layer concern that applies to service method calls regardless of whether the method was triggered by an HTTP request, a Kafka consumer, or a background scheduled job.
Q6: Can a Filter access Spring Beans?
Yes. In Spring Boot, Filters declared as @Component are full Spring Beans and support dependency injection.
Q7: What is OncePerRequestFilter?
A Spring abstract filter class that guarantees the filter method executes strictly once per request dispatch.
Q8: How to block a request inside a Servlet Filter?
Set the HTTP response status code (e.g. 401/403) and return without calling chain.doFilter().
Q9: How to block a request inside a HandlerInterceptor?
Return false from preHandle() method.
Q10: What is HandlerMethod in HandlerInterceptor?
An object representing the target Spring MVC Controller method signature and annotations.
Q11: What is the difference between preHandle, postHandle, and afterCompletion?
preHandle runs before Controller; postHandle runs after Controller before view rendering; afterCompletion runs after request is completely rendered (ideal for resource cleanup).
Q12: Does postHandle run if Controller throws an exception?
No. If an exception occurs in the Controller, postHandle is skipped, but afterCompletion STILL runs!
Q13: What is the self-invocation problem in Spring AOP?
Calling an advised method from within the same class (this.method()) bypasses the Spring AOP Proxy wrapper, causing aspects to be ignored.
Q14: Can AOP replace an Interceptor?
Not cleanly for web concerns. AOP does not have direct access to HttpServletRequest/Response objects without relying on static RequestContextHolder lookups.
Q15: Can Interceptor replace a Filter?
No. Interceptors cannot wrap request input streams or handle CORS preflight requests before DispatcherServlet execution.
Q16: Which proxy mechanism does Spring AOP use by default in Boot 2.x/3.x?
CGLIB subclass proxying.
Q17: How do you register an Interceptor in Spring Boot?
By implementing WebMvcConfigurer and overriding addInterceptors(InterceptorRegistry registry).
Q18: How do you register a Filter in Spring Boot?
By annotating it with @Component, or using a FilterRegistrationBean bean for custom URL patterns.
Q19: What is FilterChainProxy in Spring Security?
The central Spring bean that manages and executes the list of SecurityFilterChains.
Q20: What is DelegatingFilterProxy?
A standard Servlet Filter that delegates request processing to a Spring-managed Filter bean.
Q21: How do you order multiple Filters in Spring Boot?
Using the @Order annotation or FilterRegistrationBean.setOrder().
Q22: How do you order multiple Aspects in Spring AOP?
Using the @Order annotation on the Aspect classes.
Q23: How do you order multiple Interceptors in Spring MVC?
By the order they are registered in InterceptorRegistry inside WebMvcConfigurer.
Q24: What is MDC in logging and which component should populate it?
Mapped Diagnostic Context. Best populated in a Servlet Filter using MDC.put("correlationId", uuid).
Q25: Why must MDC be cleared in a finally block in Filters?
Tomcat reuses worker threads in a pool. Uncleared ThreadLocal MDC values will leak into subsequent requests!
Q26: Can AOP intercept static methods?
No. Static methods belong to the class and cannot be overridden by dynamic proxies.
Q27: Can AOP intercept private methods?
No. Spring AOP proxies cannot override or access private methods.
Q28: What is ContentCachingRequestWrapper?
A Spring Servlet Filter request wrapper that caches the InputStream bytes so the request body can be read multiple times.
Q29: What happens if an Interceptor's preHandle returns false?
The request execution halts immediately; Controller is not called, but afterCompletion runs for previously executed interceptors.
Q30: What is AsyncHandlerInterceptor?
An extension of HandlerInterceptor adding afterConcurrentHandlingStarted callback for asynchronous request processing.
Q31: What is ProceedingJoinPoint in AOP?
Parameter type used in @Around advice that provides proceed() method to run the target method.
Q32: Where does DispatcherServlet store Interceptors internally?
In a HandlerExecutionChain instance accompanying the matched handler.
Q33: Can an Interceptor catch exceptions thrown by a Controller?
Yes, the Exception instance is passed as a parameter to the afterCompletion() method.
Q34: Where should global exception handling (@RestControllerAdvice) be executed?
Inside Spring MVC after Controller execution, before Interceptor's postHandle/afterCompletion.
Q35: Do Filters execute for static resources (e.g. CSS, JS, Images)?
Yes, unless explicitly excluded via URL pattern matching in FilterRegistrationBean.
Q36: Do Interceptors execute for static resources?
Only if the resource request is mapped to a Spring MVC ResourceHttpRequestHandler.
Q37: Does AOP execute for static resources?
No, static assets do not invoke Spring Service bean methods.
Q38: How does Spring Boot register Filters automatically?
Any Spring bean implementing jakarta.servlet.Filter is automatically registered in the Tomcat filter chain.
Q39: What is the purpose of FilterRegistrationBean?
Allows registering custom Filters with specific URL patterns, order, and disabling automatic default mapping.
Q40: What is JDK Dynamic Proxy?
Java standard reflection proxy that requires the target class to implement at least one interface.
Q41: What is CGLIB?
Code Generation Library that creates dynamic runtime subclasses of target classes for proxying.
Q42: Which interception layer is best for rate limiting per IP address?
Servlet Filter (or API Gateway filter) to block malicious traffic at the earliest entry point.
Q43: Which interception layer is best for user activity auditing on service methods?
Spring AOP aspect using custom annotations like @AuditLog.
Q44: Which interception layer is best for calculation timing on web endpoints?
Spring HandlerInterceptor using preHandle and afterCompletion timestamps.
Q45: What is GenericFilterBean?
A Spring abstract class wrapping Filter to provide access to Spring Environment and bean initialization.
Q46: What happens if an exception occurs inside a Filter?
It bypasses Spring MVC @RestControllerAdvice exception handlers unless caught or forwarded to ErrorController.
Q47: How does Spring Security handle filter exceptions?
Uses ExceptionTranslationFilter inside its security filter chain to catch AccessDeniedException and AuthenticationException.
Q48: What is Pointcut in AOP?
A predicate expression that defines where Advice code should run (e.g. execution(* com.service..*.*(..))).
Q49: What is Advice in AOP?
The actual code action executed at a matched JoinPoint (@Before, @Around, @After).
Q50: What is JoinPoint in AOP?
A candidate execution point in the application (in Spring AOP, always a method execution).
Q51: What is Weaving in AOP?
The process of linking Aspects with Target Objects to create proxied objects (Spring AOP uses runtime proxy weaving).
Q52: Can an Interceptor modify the return ModelAndView?
Yes, in traditional Spring MVC HTML rendering, postHandle() receives the ModelAndView object and can modify it.
Q53: Is ModelAndView useful in REST APIs?
No, REST controllers return data objects serialized to JSON (@ResponseBody), so ModelAndView is null.
Q54: What is WebMvcConfigurer?
A Spring MVC configuration interface used to add interceptors, CORS mappings, formatters, and static resource handlers.
Q55: How to exclude URL patterns from an Interceptor?
Using registry.addInterceptor(interceptor).excludePathPatterns("/api/v1/public/**").
Q56: How to include URL patterns for a Filter?
Using filterRegistrationBean.addUrlPatterns("/api/*").
Q57: What is the impact of heavy processing inside a Filter?
Increases HTTP request latency for ALL requests passing through that filter.
Q58: What is the impact of heavy processing inside an AOP Aspect?
Increases latency for every invocation of target advised service methods.
Q59: Why can't AOP be used for CORS preflight handling?
CORS preflight (OPTIONS) requests must return headers before reaching any service or controller method; AOP runs too late.
Q60: What is the main architectural takeaway when choosing between Filter, Interceptor, and AOP?
Filter for raw Web/Servlet protocol concerns; Interceptor for Spring Web MVC endpoint concerns; AOP for core Java domain/business concerns.

20. Revision Cheatsheet

Servlet Filter: Container level · Raw HttpServletRequest/Response · Stream wrapping · CORS · Security · Runs FIRST.

Spring Interceptor: Spring MVC level · Knows HandlerMethod · preHandle/postHandle/afterCompletion · API metrics · Runs SECOND.

Spring AOP: Spring Core level · Dynamic Proxies · Any Bean Method · @Transactional · @Cacheable · Runs INSIDE Services.
