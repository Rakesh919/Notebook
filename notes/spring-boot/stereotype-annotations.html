Spring Stereotype Annotations & @Bean

The definitive production and interview guide to Spring's component model, CGLIB proxying, ASM bytecode scanning, and bean lifecycle architecture.

1. Introduction & History

In early Spring Framework (Spring 1.x), every managed component required explicit XML configuration in a central applicationContext.xml file. As enterprise applications expanded to thousands of classes, XML files became unmaintainable "XML hell."

What are Stereotype Annotations?
Stereotypes are specialized marker annotations applied to classes to denote their role within the architectural hierarchy (e.g., Web, Service, Persistence). They allow Spring’s classpath scanner to automatically discover and instantiate managed objects without manual XML or Java configuration.

Why Were They Introduced?

Spring 2.5 introduced component scanning and stereotype annotations (@Component, @Repository, @Service, @Controller) to achieve three objectives:

  • Declarative Bean Registration: Eliminate boilerplate XML <bean> declarations.
  • Domain-Driven Layering: Express the exact architectural role of a class directly in source code.
  • Targeted Cross-Cutting Behavior: Allow Aspect-Oriented Programming (AOP) aspects, exception translators, and controllers to target specific layers automatically.

Why Can't We Simply Use @Component Everywhere?

Technically, marking every class with @Component works because all stereotypes meta-inherit from @Component. However, doing so strips away specialized framework behaviors. For instance, @Repository triggers automatic database exception translation, @Controller enables Web MVC request mapping, and @Configuration activates CGLIB proxying for singleton guarantees.

2. All Spring Stereotype Annotations

Spring provides six core stereotype annotations. Below is an architectural breakdown of each:

@Component

The generic stereotype for any Spring-managed component or utility bean.

@Service

Specialization for the business logic layer. Acts as a pointcut for transaction demarcation.

@Repository

Specialization for the Data Access Object (DAO) layer. Enables SQL exception translation.

@Controller

Specialization for Spring MVC web controllers returning view names or templates.

@RestController

Composition of @Controller + @ResponseBody for RESTful JSON/XML endpoints.

@Configuration

Specialization for bean factory classes containing @Bean factory methods.

3. Why So Many Stereotype Annotations?

If all stereotypes instantiate beans inside the ApplicationContext, why didn't the Spring team stop at @Component?

1. Semantic Meaning & Domain-Driven Design (DDD)

Software architecture relies on expressiveness. When a developer inspects a class annotated with @Service, its role (business workflows, orchestration, validation) is instantly distinct from a data access class marked with @Repository.

2. Real-World Architectural Analogies

The Hospital Analogy

In a hospital, every worker is an "Employee" (@Component). But we assign specific roles: Doctor (@Service), Pharmacist (@Repository), Receptionist (@Controller). Treating everyone as a generic Employee breaks specialized operations (e.g., only Doctors perform surgery).

The Restaurant Analogy

A restaurant employs Staff. The Waiter (@Controller) receives customer orders. The Chef (@Service) prepares the meal using business rules. The Pantry Manager (@Repository) fetches ingredients from storage.

3. Layer-Specific Framework Interception

  • AOP Pointcuts: Aspects can easily target whole layers: execution(* com.app.service..*.*(..)) targeting classes annotated with @Service.
  • Exception Translation: @Repository triggers Spring's PersistenceExceptionTranslationPostProcessor, translating native SQLException or HibernateException instances into Spring's uniform DataAccessException hierarchy.
  • MVC Handler Mapping: DispatcherServlet scans only for @Controller and @RestController to register endpoint mappings during startup.

4. Internal Working & Startup Flow

How does Spring process these annotations on startup? It uses ASM bytecode scanning without loading classes into the JVM ClassLoader initially.

1
Application Startup: SpringApplication.run() initializes the AnnotationConfigApplicationContext.
↓
2
Classpath Scanning: ClassPathBeanDefinitionScanner parses package directives defined by @ComponentScan.
↓
3
ASM Bytecode Inspection: SimpleMetadataReaderFactory uses Apache Commons BCEL/ASM to read .class files as raw streams. It evaluates annotations without executing static class initializers.
↓
4
Candidate Filtering: AnnotationTypeFilter matches classes containing @Component or meta-annotated stereotypes.
↓
5
BeanDefinition Creation: Spring constructs a ScannedGenericBeanDefinition holding scope, lazy status, and autowiring metadata.
↓
6
BeanFactory Registration: The BeanDefinition is registered in the DefaultListableBeanFactory map under its generated bean name.
↓
7
Instantiation & Dependency Injection: Non-lazy singletons are instantiated, injected with dependencies, processed by BeanPostProcessors, and initialized.

5. @Component Deep Dive

@Component is the foundational stereotype annotation defined in package org.springframework.stereotype.

package com.devvault.utils;

import org.springframework.stereotype.Component;

@Component
public class DataHashingUtility {
    public String hash(String input) {
        return Integer.toHexString(input.hashCode());
    }
}

Generated Bean Name Conventions

By default, Spring uses AnnotationBeanNameGenerator. If no name is specified in @Component("customName"), Spring converts the simple class name to decapitalized camelCase (e.g., DataHashingUtility → dataHashingUtility). Exception: If the first two letters are uppercase, the original casing is preserved (e.g., URLParser → URLParser).

6. @Service Deep Dive

@Service decorates classes in the business layer that execute domain transactions and business workflows.

package com.devvault.service;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class OrderProcessingService {
    
    @Transactional
    public void processOrder(String orderId) {
        // Business rules, payment gateways, and inventory allocation
    }
}
Production Best Practice: Do not place database persistence logic or HTTP handling inside @Service classes. Keep services framework-agnostic where possible, taking in DTOs/Domain Models and returning clean entities or responses.

8. @Controller Deep Dive

@Controller serves as the presentation component in traditional Spring MVC applications. It returns view template names resolved by a ViewResolver (e.g., Thymeleaf, HTML).

@Controller
public class WebPageController {

    @GetMapping("/dashboard")
    public String getDashboard(Model model) {
        model.addAttribute("user", "Admin");
        return "dashboard"; // Resolves to templates/dashboard.html
    }
}

9. @RestController Deep Dive

@RestController is a meta-annotation composed of @Controller and @ResponseBody. Instead of returning rendered HTML views, handler methods serialize return objects directly into HTTP response bodies (JSON or XML) via HttpMessageConverter (typically Jackson).

@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Controller
@ResponseBody
public @interface RestController {
    String value() default "";
}

10. @Configuration Deep Dive

@Configuration classes define Spring factory methods annotated with @Bean. Spring uses CGLIB byte-code generation to proxy @Configuration classes in Full Mode.

CGLIB Enhancement & Method Interception:
When a class is marked with @Configuration (or proxyBeanMethods = true), Spring generates a runtime CGLIB subclass. When one @Bean method calls another @Bean method internally, the CGLIB proxy intercepts the call, checking the BeanFactory first to guarantee singleton instances instead of re-executing raw Java methods.

11. @Bean Annotation Complete Deep Dive

While stereotypes are applied at class level for automatic scanning, @Bean is applied at method level to explicitly instantiate and return objects.

Why Does @Bean Exist if We Have @Component?

  • Third-Party Libraries: You cannot add @Component to a class inside an external compiled .jar file (e.g., RedisTemplate, RestTemplate, DataSource).
  • Complex Custom Instantiation: When creating an object requires intricate builder pattern configurations, reading environment properties, or executing complex initialization code.
  • Conditional Creation: Toggle bean creation dynamically based on runtime conditions using @ConditionalOnProperty, @ConditionalOnClass, or profiles.
@Configuration
public class AppInfrastructureConfig {

    @Bean(initMethod = "start", destroyMethod = "stop")
    @Scope("singleton")
    @Lazy
    public ExternalQueueClient queueClient() {
        return new ExternalQueueClient("tcp://localhost:61616");
    }
}

12. @Component vs @Bean

Understanding when to choose class-level stereotypes versus explicit method-level factory beans:

14. Production Project Walkthrough

Below is a clean architecture walkthrough illustrating proper layer decoupling in a production system:

// 1. REST Controller Layer
@RestController
@RequestMapping("/api/v1/users")
public class UserController {
    private final UserService userService;
    public UserController(UserService userService) { this.userService = userService; }

    @PostMapping
    public ResponseEntity<User> createUser(@RequestBody UserDto dto) {
        return ResponseEntity.ok(userService.register(dto));
    }
}

// 2. Service Layer
@Service
public class UserService {
    private final UserRepository userRepo;
    public UserService(UserRepository userRepo) { this.userRepo = userRepo; }

    @Transactional
    public User register(UserDto dto) {
        return userRepo.save(new User(dto.getName()));
    }
}

// 3. Repository Layer
@Repository
public class UserRepositoryImpl implements UserRepository {
    // Persistence logic
}

15. Common Production Mistakes

1. Using @Component Everywhere: Strips away exception translation on repositories and transaction pointcuts on services.
2. Calling @Bean Methods inside @Component Classes: Without @Configuration CGLIB proxying, inter-bean method calls execute plain Java code, instantiating duplicate non-singleton objects.
3. Package Scanning Mismatches: Placing components outside the package hierarchy of the @SpringBootApplication class without declaring explicit scanBasePackages.

16. Top 50 Interview QA

Key technical interview questions and answers for Senior Spring Boot Developer roles:

Q1: How does @Repository handle exception translation internally?
Spring applies PersistenceExceptionTranslationPostProcessor to beans marked with @Repository. It wraps the bean in an AOP interceptor that catches technology-specific exceptions (JPA, Hibernate, JDBC) and translates them using PersistenceExceptionTranslator into Spring's DataAccessException hierarchy.
Q2: What happens if I call a @Bean method from another @Bean method in a @Component class versus a @Configuration class?
In a @Configuration class, Spring proxies the class using CGLIB (Full Mode). Calling a @Bean method retrieves the existing singleton instance from the BeanFactory. In a @Component class (Lite Mode), CGLIB proxying is disabled; calling the method invokes standard Java execution, creating a second unmanaged instance.
Q3: Does Spring load classes into JVM memory during component scanning?
No. Spring uses ASM bytecode reading via SimpleMetadataReaderFactory to inspect .class streams without passing them to the JVM ClassLoader. This speeds up boot times and prevents premature static initialization.
Q4: What is the difference between @Controller and @RestController?
@RestController is meta-annotated with @Controller and @ResponseBody. While @Controller expects handler methods to return view names for rendering (e.g. HTML/Thymeleaf), @RestController automatically serializes method return values directly into the HTTP response body as JSON/XML using HttpMessageConverters.
Q5: Why can't we use @Component for 3rd party classes?
@Component requires editing source code to place the annotation above the class definition. Since 3rd party dependencies are compiled into .class files inside JARs, you must use @Bean inside a @Configuration class to declare third-party beans.
Q6: What is the proxyBeanMethods attribute in @Configuration?
Introduced in Spring 5.2, setting proxyBeanMethods = false disables CGLIB subclass generation for @Configuration classes (Lite Mode). This improves startup performance and reduces memory overhead when inter-bean method calls are not used.
Q7: Can a class have multiple stereotype annotations?
Technically Java allows stacking annotations, but doing so creates conflicting framework behavior (e.g., mixing MVC controller mapping with repository exception translation). Architecture requires assigning a single primary stereotype per class based on its layer.
Q8: How does Spring resolve bean name collisions during scanning?
If two scanned components resolve to the same bean name in the same context, Spring throws a ConflictingBeanDefinitionException during startup unless explicitly overridden using custom names or primary qualifiers.
Q9: What is the default scope of beans created via @Component or @Bean?
The default scope is Singleton. Spring creates one shared instance per ApplicationContext container.
Q10: What is the difference between @Autowired and @Bean?
@Autowired is an injection annotation used to request a dependency instance. @Bean is a factory method creation annotation used to register an instance inside the container.
Q11: How does @ComponentScan work when no base packages are specified?
It defaults to scanning the package of the class declaring the @ComponentScan or @SpringBootApplication annotation, including all sub-packages underneath it.
Q12: Can we declare @Bean methods as static?
Yes. Static @Bean methods are invoked without instantiating their enclosing @Configuration class, which is necessary when registering early infrastructure beans like BeanFactoryPostProcessor.
Q13: What is Lite Mode in Spring configuration?
Lite Mode occurs when @Bean methods are defined inside plain @Component classes or when proxyBeanMethods = false is set on a @Configuration class. CGLIB proxying is bypassed.
Q14: How does Spring's @Repository know which database exceptions to translate?
It uses persistence translators like SQLExceptionTranslator or PersistenceExceptionTranslator configured for specific ORMs (Hibernate/JPA) to map SQL error codes to Spring's DataAccessException hierarchy.
Q15: What annotation is used to lazily initialize a stereotype bean?
The @Lazy annotation. It defers bean creation until the bean is requested for the first time instead of during application startup.
Q16: How do you register a prototype-scoped bean using @Bean?
By decorating the @Bean method with @Scope("prototype") or @Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE).
Q17: Is @Service required for a service class to participate in transactions?
No. Transactional behavior is driven by @Transactional and Spring AOP. However, @Service provides architectural clarity and allows layer-specific pointcut expressions.
Q18: What is meta-annotation in Spring?
An annotation applied to another annotation. For instance, @Service is meta-annotated with @Component, allowing scanners to recognize it as a Spring component.
Q19: How to override a bean definition in Spring Boot?
By setting spring.main.allow-bean-definition-overriding=true in application.properties or using @Primary / @ConditionalOnMissingBean.
Q20: What is the role of @Indexed in Spring 5?
An annotation from org.springframework.stereotype that generates an index file (META-INF/spring.components) at compile time to speed up classpath scanning in massive applications.
Q21: Difference between @Primary and @Qualifier?
@Primary sets a default fallback preference when multiple beans match a injection candidate type. @Qualifier provides specific, explicit bean name targeting at the injection point.
Q22: Can a @Bean method return void?
No. A @Bean method must return an object instance to register inside the ApplicationContext container. Returning void causes startup errors.
Q23: How to define custom init and destroy methods on @Bean?
Using attributes: @Bean(initMethod = "customInit", destroyMethod = "customDestroy").
Q24: What happens if a @Service bean throws an unhandled RuntimeException?
If wrapped inside a @Transactional boundary, Spring AOP catches the RuntimeException and triggers a database transaction rollback.
Q25: Why is Constructor Injection preferred over @Autowired on fields?
Constructor injection guarantees immutability (final fields), prevents NullPointerException during unit tests without Spring runner, and prevents circular dependencies at startup.
Q26: Can we use @PostConstruct with @Bean?
Yes. Any object created by Spring (whether via @Component or @Bean) undergoes BeanPostProcessor execution, triggering @PostConstruct methods.
Q27: Difference between @Component and @Configuration?
Both register components, but @Configuration classes are enhanced with CGLIB proxies to intercept inter-bean method calls and enforce singleton semantics.
Q28: How does Spring Boot discover auto-configuration classes?
By reading the META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports file using Spring Factories loader.
Q29: Can @Repository be used with Spring Data JPA interfaces?
Spring Data JPA interfaces extending JpaRepository do not strictly require @Repository because Spring Data infrastructure automatically discovers and creates proxy instances for them.
Q30: What is AnnotationConfigApplicationContext?
A standalone application context implementation that accepts annotated classes (stereotypes and configurations) directly as input for bean registration.
Q31: How to exclude specific components from @ComponentScan?
Using the excludeFilters attribute of @ComponentScan with custom regex or annotation type filters.
Q32: Is @RestController thread-safe?
Because controllers are singleton by default, they are thread-safe only if they are stateless. Holding mutable instance state in a singleton controller introduces race conditions.
Q33: Can we inject prototype beans into a singleton bean safely?
Not directly via field injection, because the singleton is injected only once at startup. You must use @Lookup method injection or ObjectProvider<T>.
Q34: How to name a bean created via @Bean?
By setting the value attribute: @Bean(name = "customBeanName") or @Bean("customBeanName").
Q35: What happens if two @Bean methods in different configuration classes have identical names?
Unless bean overriding is allowed, the last loaded bean definition will overwrite the former, or Spring Boot will throw a BeanDefinitionOverrideException.
Q36: Why should business logic not be written inside Controller methods?
It violates Single Responsibility Principle (SRP), prevents reusability across multiple controllers or asynchronous workers, and makes unit testing difficult.
Q37: What is the purpose of @ResponseBody?
It tells Spring MVC that the method return value should be bound directly to the HTTP response payload body rather than rendered as a template view name.
Q38: How does Spring match HTTP requests to @RestController handler methods?
Via RequestMappingHandlerMapping, which scans @Controller and @RestController beans to construct lookup tables matching HTTP path, method, headers, and media types.
Q39: Does @Component work on abstract classes?
Spring scans the abstract class definition, but it cannot instantiate an abstract class directly. It will instantiate concrete subclasses that inherit the stereotype.
Q40: How to conditionalize a @Bean on a configuration property?
Decorate the @Bean method with @ConditionalOnProperty(name = "feature.enabled", havingValue = "true").
Q41: Difference between @ControllerAdvice and @Controller?
@Controller handles specific web requests. @ControllerAdvice is a specialization used for cross-cutting global exception handling and model formatting across all controllers.
Q42: What is a BeanDefinition?
An internal Spring interface that holds metadata describing a bean instance, including its class name, scope, factory method, properties, constructor arguments, and initialization lifecycle handlers.
Q43: What interface does Spring use to scan bytecode?
org.springframework.core.type.classreading.MetadataReader backed by ASM framework.
Q44: What is the purpose of @Order with Spring stereotypes?
It controls the sorting order when injecting a List<T> of beans matching the same interface type.
Q45: Can @Service call another @Service?
Yes. Service orchestration is standard practice where high-level domain workflows compose fine-grained business logic services.
Q46: What is the role of HttpMessageConverter?
A Spring strategy interface used by @ResponseBody / @RequestBody to marshal Java objects into HTTP response formats (JSON/XML) and unmarshal HTTP request payloads back into Java objects.
Q47: Why does Spring recommend package-private constructors for components?
It prevents external classes outside the package from instantiating the component manually without Spring management, while allowing Spring reflection and local unit tests to execute cleanly.
Q48: What is CGLIB?
Code Generation Library. A high-level bytecode generation library used by Spring to create runtime subclasses for proxying classes lacking interfaces, such as @Configuration classes.
Q49: What is the impact of @Configuration(proxyBeanMethods = false)?
It turns off CGLIB proxying for the configuration class, improving performance and startup memory usage while switching bean processing to Lite Mode.
Q50: What is the main architectural goal of Spring stereotypes?
To enforce clear separation of concerns (SoC), enable automatic declarative component management, and allow targeted cross-cutting framework features across enterprise layers.

17. Production Best Practices

  • Strict Layer Separation: Controllers handle HTTP contracts; Services handle business rules; Repositories handle persistence. Never bleed persistence code into controllers.
  • Constructor Injection: Always use constructor injection for required dependencies. Mark injected fields as final.
  • Use @Bean for Infrastructure: Reserve @Bean for third-party client integrations (Redis, Kafka, RestTemplate) and complex multi-property factory setups.
  • Enable proxyBeanMethods = false: If configuration classes do not execute inter-bean method calls, disable CGLIB proxying to save memory and improve startup speed.

18. Quick Revision Cheat Sheet

@Component: Generic component. Use for helpers and utilities.

@Service: Business layer. Use for workflows and transactional boundaries.

@Repository: Data access layer. Translates database exceptions automatically.

@Controller: MVC Web Controller returning HTML view template paths.

@RestController: REST API Controller returning serialized JSON/XML payloads directly.

@Configuration: Factory setup class enhanced via CGLIB for singleton bean management.

@Bean: Explicit method-level factory registration for third-party libraries and complex setups.
