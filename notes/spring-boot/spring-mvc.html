Spring MVC — Complete Deep Dive

A beginner-friendly, simple, and comprehensive guide to Spring MVC—explaining the Front Controller pattern, DispatcherServlet, request lifecycles, RESTful serialization, exception handling, and production architectures.

1. Introduction

Before modern web frameworks, building Java web applications required writing bare-metal Java Servlets. Every single URL endpoint required its own Servlet class, manual HTML string concatenation, manual parameter parsing, and explicit thread synchronization. This produced messy, unmaintainable code.

Spring MVC (Model-View-Controller) was introduced to solve this exact problem. It provides an elegant, structured framework for building decoupled web applications and RESTful Web Services in Java.

Real-World Analogy: The Restaurant Flow

Imagine a busy restaurant. Instead of customers walking into the kitchen to talk directly to individual chefs, a Receptionist / Maître D' greets customers at the door, assigns them a waiter, passes order slips to the kitchen staff, and delivers the cooked meal back to the table. In Spring MVC, this central coordinator is called the DispatcherServlet!

Advantages of Spring MVC
  • Separation of Concerns: Web UI, business logic, and database access are strictly separated into clean layers.
  • Reusable Components: Interceptors, exception handlers, and converters apply across all endpoints seamlessly.
  • Annotation-Driven: Routing and parameter parsing are handled via declarative annotations like @GetMapping and @PathVariable.

2. MVC Architecture

The MVC pattern breaks a web application down into three distinct logical components:

1. Model

Represents the application's domain data and state (DTOs, Entities, and data models). It carries data between the Controller and the UI or REST client.

2. View

Represents the presentation output (e.g. HTML templates generated by Thymeleaf/JSP, or JSON payloads rendered in REST endpoints).

3. Controller

Contains the routing logic. It receives HTTP requests, processes input parameters, calls business services, and selects the appropriate View or JSON response.

Classic MVC Data Flow

1
User Action: Client submits an HTTP request to the Controller.
↓
2
Business Execution: Controller updates/fetches the Model via Service classes.
↓
3
Response Rendering: Controller passes the Model data to the View layer (or Jackson JSON serializer) to produce output.

3. Complete Request Lifecycle

What happens step-by-step when a user types a URL or your frontend sends a REST API request? Here is the complete end-to-end execution path:

End-to-End Spring MVC Request Lifecycle

1
HTTP Request: Browser sends POST /api/v1/orders.
↓
2
Embedded Tomcat: Web server accepts TCP connection and passes the raw request to the Servlet container.
↓
3
DispatcherServlet: The central Front Controller intercepts the incoming request.
↓
4
HandlerMapping: DispatcherServlet asks HandlerMapping to locate the matching Controller method.
↓
5
HandlerAdapter: Invokes the target method, parsing parameters and unmarshalling JSON body payloads.
↓
6
Controller Method: Executes user controller method (e.g. OrderController.createOrder()).
↓
7
Service Layer: Runs business logic, validation rules, and transaction boundaries (@Transactional).
↓
8
Repository Layer: Queries the database via Spring Data JPA / Hibernate.
↓
9
Database execution: PostgreSQL executes SQL query and returns row records.
↓
10
Return Object: Service returns domain Entity / DTO back to the Controller.
↓
11
HttpMessageConverter: Jackson (MappingJackson2HttpMessageConverter) serializes the Java object to JSON.
↓
12
HTTP 200 OK Response: DispatcherServlet flushes JSON response through Tomcat back to Browser.

4. DispatcherServlet

The DispatcherServlet is the beating heart of Spring MVC. It implements the Front Controller Architectural Pattern—a design pattern where a single centralized Servlet intercepts all incoming HTTP traffic for a web application and delegates routing, parameter parsing, and response rendering to specialized helper components.

Responsibilities of DispatcherServlet
  • Interceptors pre-processing and post-processing execution.
  • Consulting HandlerMapping to resolve controller target methods.
  • Invoking HandlerAdapter to resolve parameters and run methods.
  • Delegating global exception handling to HandlerExceptionResolver.
  • Marshalling Java objects to JSON via HttpMessageConverters.

5. HandlerMapping

When a request arrives at DispatcherServlet, how does Spring know which class or method should handle it? It consults the HandlerMapping component.

During startup, Spring's RequestMappingHandlerMapping scans all beans annotated with @Controller and @RestController, building an in-memory lookup table of URL paths, HTTP methods, headers, and media types mapped directly to Java methods.

@RestController
@RequestMapping("/api/v1/users")
public class UserController {

    // HandlerMapping registers: GET /api/v1/users/{id} -> getUserById()
    @GetMapping("/{id}")
    public UserDto getUserById(@PathVariable("id") Long id) {
        return userService.findById(id);
    }
}

6. HandlerAdapter

Once HandlerMapping identifies the target controller method, DispatcherServlet does not invoke the Java method directly via reflection. Instead, it delegates invocation to a HandlerAdapter (specifically RequestMappingHandlerAdapter).

Why Use HandlerAdapter?
Controller methods have completely dynamic signatures! One method might take @RequestBody UserDto dto, while another takes @RequestParam String query, HttpServletRequest req. HandlerAdapter uses HandlerMethodArgumentResolver implementations to evaluate and inject whatever parameters the target method requests before calling it.

7. Controller Layer

Spring MVC provides two primary annotations to declare web controller components:

Annotation Primary Use Case Response Behavior
@Controller Traditional Server-Side Rendering (Thymeleaf, JSP, HTML views). Handler methods return a String representing a View Template Name.
@RestController RESTful Web APIs (React, Angular, Mobile Apps, Microservices). Meta-annotated with @Controller + @ResponseBody. Returns objects directly serialized as JSON/XML.

8. Request Mapping Annotations

Spring MVC provides declarative mapping annotations to inspect HTTP parameters, paths, headers, and request payloads:

HTTP Verb Mappings

@GetMapping, @PostMapping, @PutMapping, @DeleteMapping, @PatchMapping. Shorthands for @RequestMapping(method = RequestMethod...).

@PathVariable

Extracts dynamic values directly from URI path segments (e.g. /users/{id} → @PathVariable Long id).

@RequestParam

Extracts query parameters or form fields from the URL (e.g. /users?page=1&size=10 → @RequestParam int page).

@RequestBody

Instructs Jackson to deserialize the incoming HTTP request JSON body into a target Java DTO object.

@RequestHeader & @CookieValue

Extracts specific HTTP headers (e.g. Authorization, X-Correlation-ID) or HTTP cookies.

@ResponseStatus

Sets explicit HTTP response status codes (e.g., HttpStatus.CREATED 201 or HttpStatus.NO_CONTENT 204).

9. Request & Response Serialization

How does Spring automatically convert JSON sent from a frontend into a Java object, and then convert Java objects back into JSON for the HTTP response?

It uses HttpMessageConverters. For REST APIs returning JSON, Spring MVC configures the Jackson library (MappingJackson2HttpMessageConverter) by default.

Jackson Conversion Pipeline

1
Deserialization: Incoming JSON string stream → Jackson ObjectMapper → Instantiates Java DTO (used by @RequestBody).
2
Serialization: Returned Java DTO / Response Entity → Jackson ObjectMapper → Generates outgoing JSON string bytes (used by @ResponseBody).

10. Validation Framework

Spring MVC integrates seamlessly with Jakarta Bean Validation (Hibernate Validator) to validate incoming request DTOs automatically.

public class UserRegistrationRequest {

    @NotBlank(message = "Name cannot be blank")
    private String name;

    @Email(message = "Must be a valid email address")
    @NotNull
    private String email;

    @Size(min = 8, max = 32, message = "Password must be between 8 and 32 characters")
    private String password;
}

@RestController
@RequestMapping("/api/v1/users")
public class UserController {

    @PostMapping
    public ResponseEntity<Void> register(@Valid @RequestBody UserRegistrationRequest request) {
        // If validation fails, Spring throws MethodArgumentNotValidException automatically!
        userService.create(request);
        return ResponseEntity.status(HttpStatus.CREATED).build();
    }
}

11. Global Exception Handling

In production applications, you should never allow raw Java exceptions or stack traces to leak to REST API clients. Spring MVC provides @RestControllerAdvice for centralized, clean error handling.

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(UserNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ErrorResponse handleUserNotFound(UserNotFoundException ex) {
        return new ErrorResponse("USER_NOT_FOUND", ex.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorResponse handleValidationFailure(MethodArgumentNotValidException ex) {
        String firstError = ex.getBindingResult().getFieldErrors().get(0).getDefaultMessage();
        return new ErrorResponse("VALIDATION_FAILED", firstError);
    }
}

12. Interceptors

HandlerInterceptors allow you to intercept HTTP requests before they reach a controller method, after execution completes, or after the view/response has been fully rendered.

HandlerInterceptor Lifecycle

1
preHandle(): Executes before reaching the controller. Returning false aborts request execution immediately.
↓
2
Controller Method: Executes business code in controller.
↓
3
postHandle(): Executes after controller finishes, before view rendering / JSON flushing.
↓
4
afterCompletion(): Executes after full request completion (used for resource cleanups or logging total execution time).

13. Filters vs Interceptors

Developers often confuse Servlet Filters with Spring HandlerInterceptors. Here is how they differ:

Feature Servlet Filter Spring HandlerInterceptor
Specification Layer Standard Jakarta Servlet Specification (Outside Spring). Native Spring MVC Framework component.
Execution Location Runs before DispatcherServlet gets invoked. Runs inside DispatcherServlet, right before reaching Controller.
Spring Context Access Limited (requires Spring Bean Delegation). Full access to Spring ApplicationContext and target HandlerMethod objects.
Common Use Cases GZIP compression, CORS preflight headers, raw request security, rate limiting. Request timing logs, correlation ID tracing, custom auth token checks, locale updates.

14. View Resolution

In traditional web applications returning HTML templates (e.g. Thymeleaf), controllers return a String view name (e.g. "index"). The ViewResolver maps this string to a physical template file (e.g., /templates/index.html).

In modern REST APIs using @RestController, the ViewResolver is completely bypassed because objects are converted directly to JSON streams via HttpMessageConverters.

15. REST API Best Practices

  • Use Proper Nouns for Resources: Use plural nouns for endpoints (/api/v1/orders, /api/v1/users) instead of verbs (/getOrders).
  • Leverage Proper HTTP Verbs: GET (Read), POST (Create), PUT (Replace), PATCH (Partial Update), DELETE (Remove).
  • Return Meaningful HTTP Status Codes: 200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 500 Internal Server Error.
  • API Versioning: Include version prefixes in path URIs (e.g. /api/v1/products).

16. Real Production Walkthrough

Here is how a clean multi-layered Spring Boot REST API handles an HTTP request in production:

// 1. Controller Layer: Routing, Input Validation, HTTP Status Codes
@RestController
@RequestMapping("/api/v1/products")
public class ProductController {

    private final ProductService productService;
    public ProductController(ProductService productService) { this.productService = productService; }

    @PostMapping
    public ResponseEntity<ProductResponseDto> create(@Valid @RequestBody CreateProductRequest request) {
        ProductResponseDto response = productService.createProduct(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(response);
    }
}

// 2. Service Layer: Business Logic & Transactions
@Service
public class ProductServiceImpl implements ProductService {

    private final ProductRepository repository;
    public ProductServiceImpl(ProductRepository repository) { this.repository = repository; }

    @Override
    @Transactional
    public ProductResponseDto createProduct(CreateProductRequest request) {
        Product entity = new Product(request.getName(), request.getPrice());
        Product saved = repository.save(entity);
        return new ProductResponseDto(saved.getId(), saved.getName(), saved.getPrice());
    }
}

17. Common Mistakes

1. Business Logic Inside Controller: Writing SQL queries, database calls, or calculations inside controller methods makes code un-testable and breaks Separation of Concerns.

2. Returning JPA Entities Directly from Controllers: Causes infinite JSON recursion loops (due to bidirectional relationships) and exposes internal database schema. Always return DTOs.

3. Missing @Valid Annotation: Forgetting to add @Valid next to @RequestBody parameters skips Bean Validation checks entirely.

18. Senior Best Practices

  • Use DTOs (Data Transfer Objects) for request payloads and response bodies. Never expose JPA Entities.
  • Centralize all exception handling inside a @RestControllerAdvice class.
  • Use Constructor Injection for Service dependencies in Controllers and mark fields private final.

19. 50+ Interview Questions

Q1: What is DispatcherServlet in Spring MVC?
It is the central Front Controller Servlet in Spring MVC that intercepts all incoming HTTP requests and coordinates routing, execution, exception handling, and response rendering.
Q2: Why is DispatcherServlet called a Front Controller?
Because it acts as a single centralized entry point for all web requests, delegating specialized tasks (like endpoint lookup or parameter conversion) to helper beans.
Q3: Difference between @Controller and @RestController?
@Controller is used for traditional HTML view rendering. @RestController combines @Controller and @ResponseBody to automatically serialize return objects into JSON/XML payloads.
Q4: What is HandlerMapping?
A Spring component that maintains a lookup table of request URLs/HTTP methods and returns the matching Controller handler method.
Q5: What is HandlerAdapter?
A component that invokes the controller method chosen by HandlerMapping, resolving dynamic method arguments and parameters before execution.
Q6: What is HttpMessageConverter?
A Spring strategy interface used by Jackson to convert Java objects into HTTP response JSON streams and vice versa.
Q7: Difference between Servlet Filter and HandlerInterceptor?
Filters are Jakarta Servlet specs that run before DispatcherServlet. Interceptors are Spring components that run inside DispatcherServlet around Controller execution.
Q8: How does @RestControllerAdvice work?
It acts as a global exception interceptor class for all controllers, using @ExceptionHandler methods to return standardized JSON error responses.
Q9: Difference between @PathVariable and @RequestParam?
@PathVariable extracts dynamic path segments (/users/{id}). @RequestParam extracts query parameters (/users?id=10).
Q10: What does @RequestBody do?
Tells Jackson to deserialize the incoming HTTP request JSON body into a Java DTO object.
Q11: What does @ResponseBody do?
Tells Spring MVC to serialize the method return value directly into the HTTP response body as JSON.
Q12: What is the purpose of @Valid annotation?
Triggers automatic Bean Validation on input DTO fields before executing the controller method.
Q13: What exception is thrown when @Valid fails on @RequestBody?
MethodArgumentNotValidException.
Q14: What is the role of ViewResolver in Spring MVC?
Maps string view names returned by @Controller methods to physical view template files (e.g. Thymeleaf HTML).
Q15: Why is ViewResolver bypassed in REST APIs?
Because @RestController methods return raw data objects serialized directly to JSON via HttpMessageConverter rather than HTML views.
Q16: What is preHandle() in HandlerInterceptor?
Method that executes before reaching the controller; returning false aborts the request execution immediately.
Q17: What is postHandle() in HandlerInterceptor?
Method that executes after controller method completion but before response rendering/flushing.
Q18: What is afterCompletion() in HandlerInterceptor?
Method that executes after the complete HTTP request has finished rendering, used for resource cleanup.
Q19: What is @CrossOrigin used for?
Enables Cross-Origin Resource Sharing (CORS) headers on endpoints for frontend integration.
Q20: What is @ResponseStatus used for?
Sets default HTTP status code (e.g., 201 CREATED) on controller methods or custom exception classes.
Q21: How to get HTTP request headers in Spring MVC?
Using the @RequestHeader parameter annotation.
Q22: How to get HTTP cookies in Spring MVC?
Using the @CookieValue parameter annotation.
Q23: Difference between PUT and PATCH?
PUT replaces an entire resource record. PATCH performs a partial update on specific fields.
Q24: What is ResponseEntity in Spring MVC?
A wrapper object allowing full control over HTTP response status code, headers, and body payload.
Q25: Why should you never return JPA Entities directly from REST controllers?
Prevents infinite JSON recursion loops, leaks database structure, and exposes internal security fields.
Q26: What is MethodArgumentTypeMismatchException?
Thrown when a request path or query parameter cannot be converted to the required Java target type.
Q27: How does Spring MVC handle file uploads?
Using MultipartFile parameter type supported by StandardServletMultipartResolver.
Q28: What is @ModelAttribute used for?
Binds form data or query parameters to a model object in traditional MVC HTML applications.
Q29: How to customize Jackson ObjectMapper in Spring Boot?
By defining a custom Jackson2ObjectMapperBuilderCustomizer or ObjectMapper bean.
Q30: What is Content Negotiation in Spring MVC?
Determining the response media type (JSON vs XML) based on the HTTP Accept header.
Q31: What is @ExceptionHandler?
Annotation used to define handler methods for specific exception types inside controllers or advice classes.
Q32: Difference between @ControllerAdvice and @RestControllerAdvice?
@RestControllerAdvice automatically adds @ResponseBody to all error handler method returns.
Q33: How to validate URL PathVariables?
Add @Validated on the Controller class level and validation annotations (e.g. @Min(1)) on path variable parameters.
Q34: How to configure Interceptors in Spring Boot?
By implementing WebMvcConfigurer and overriding addInterceptors() method.
Q35: What HTTP status code should be returned on successful creation?
201 Created.
Q36: What HTTP status code should be returned on successful deletion?
204 No Content (or 200 OK).
Q37: What is RequestMappingHandlerAdapter?
Concrete implementation of HandlerAdapter used to execute @RequestMapping methods.
Q38: What is RequestMappingHandlerMapping?
Concrete implementation of HandlerMapping that maps URLs to @RequestMapping methods.
Q39: What is the default JSON library in Spring Boot Web?
Jackson.
Q40: How to handle CORS globally in Spring MVC?
By overriding addCorsMappings() inside a WebMvcConfigurer bean.
Q41: What is HttpEntity?
Represents an HTTP request or response entity consisting of headers and body.
Q42: Can a Controller method take HttpServletRequest as argument?
Yes! HandlerAdapter resolves raw Servlet API parameters automatically.
Q43: What is UriComponentsBuilder?
A builder class used to construct and expand URI strings safely in Spring.
Q44: What happens if a required @RequestParam is missing in request?
Spring throws MissingServletRequestParameterException returning HTTP 400.
Q45: How to make a @RequestParam optional?
Set @RequestParam(required = false) or wrap parameter in Optional<T>.
Q46: What is Matrix Variable in Spring MVC?
Name-value pairs embedded in path segments separated by semicolons (/users;age=30).
Q47: What is ProblemDetail in Spring 6 / Boot 3?
A standard specification (RFC 7807) representation for returning structured REST API error responses.
Q48: What is WebMvcConfigurer?
An interface used to customize Spring MVC configuration (CORS, Interceptors, Formatters).
Q49: How does Spring MVC handle async request processing?
By allowing controller methods to return CompletableFuture<T> or DeferredResult<T>.
Q50: What is the main takeaway of Spring MVC architecture?
Centralized Front Controller routing, clean layered decoupling, annotation-driven parameter resolution, and automated REST JSON serialization.
