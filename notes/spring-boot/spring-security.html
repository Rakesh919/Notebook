Spring Security — Complete Deep Dive

A beginner-friendly, simple, and comprehensive handbook covering Authentication, Authorization, Filter Chains, BCrypt, JWT, OAuth2, Session Management, CORS, CSRF, and production best practices.

1. Introduction

In modern web applications, security is not an afterthought or an optional feature—it is an absolute necessity. Unprotected APIs can leak sensitive user data, allow unauthorized administrative actions, or expose internal databases to malicious attacks.

Spring Security is a powerful, highly customizable framework for Java applications that focuses on providing both Authentication and Authorization. It acts as a protective shield sitting in front of your Spring Boot web application, inspecting every single incoming HTTP request before it can ever touch your business logic or controllers.

Real-World Analogy: An Airport Checkpoint

Imagine going on an international flight. First, at the entrance terminal, security guards check your Passport and ID to confirm who you are (Authentication). Then, at the boarding gate, the airline staff checks your Ticket Class to see if you are allowed to enter the First Class Lounge or board the plane (Authorization).

Why Use Spring Security?

Instead of writing custom security filters, password hashing routines, and token verification logic from scratch (which often introduces critical security loopholes), Spring Security provides battle-tested, industry-standard protections against common vulnerabilities out of the box.

2. Authentication vs Authorization

The two foundational pillars of application security are often confused, but they address entirely different questions:

The Security Pipeline

1
Authentication ("Who are you?"): Validating identity credentials (e.g. Username/Password, OTP, JWT Token, Biometrics).
↓
2
Authorization ("What can you do?"): Checking roles and permissions (e.g. Can an USER role access DELETE /admin/users?).
Dimension Authentication Authorization
Core Question Who are you? (Identity Verification) What are you allowed to access? (Permission Check)
Execution Timing Executes first in the security chain. Executes after authentication succeeds.
Failure HTTP Status 401 Unauthorized 403 Forbidden
Common Mechanism Passwords, Tokens (JWT), OAuth2 Login Roles (ROLE_ADMIN), Authorities (READ_PRIVILEGE)

3. Spring Security Architecture

At its core, Spring Security's web protection engine is built entirely on standard Jakarta Servlet Filters. It intercepts requests before they reach the DispatcherServlet.

Complete End-to-End Component Hierarchy

1
HTTP Request: Arrives at Embedded Tomcat / Servlet Container.
↓
2
DelegatingFilterProxy: Standard Servlet Filter that delegates incoming requests to Spring-managed beans.
↓
3
FilterChainProxy & SecurityFilterChain: Evaluates the ordered sequence of Spring Security filters.
↓
4
Authentication Filter: Extracts credentials (e.g. UsernamePasswordAuthenticationFilter / JwtAuthenticationFilter).
↓
5
AuthenticationManager: Central manager (ProviderManager) delegating authentication tasks.
↓
6
AuthenticationProvider: Executes actual validation logic (e.g., DaoAuthenticationProvider).
↓
7
UserDetailsService & PasswordEncoder: Loads user from DB and verifies BCrypt hashed passwords.
↓
8
SecurityContextHolder: Stores the fully authenticated user object in current ThreadLocal storage.

4. Security Filter Chain

The SecurityFilterChain is a bean containing an ordered chain of security filters. Each filter inspects or modifies the request before passing it down the chain using filterChain.doFilter(request, response).

Key Spring Security Filters in Order
  • ChannelProcessingFilter: Redirects HTTP to HTTPS.
  • CorsFilter: Handles Cross-Origin Resource Sharing preflight requests.
  • CsrfFilter: Validates CSRF tokens for stateful session applications.
  • LogoutFilter: Handles user logout requests.
  • UsernamePasswordAuthenticationFilter: Processes form-based login submissions.
  • BearerTokenAuthenticationFilter / Custom JwtFilter: Validates JWT headers.
  • FilterSecurityInterceptor / AuthorizationFilter: Performs final authorization checks.

5. Authentication Flow

Here is step-by-step how Spring Security processes a traditional username/password authentication request:

1
User submits credentials (username & password).
2
UsernamePasswordAuthenticationFilter creates an unauthenticated UsernamePasswordAuthenticationToken.
3
Passes token to AuthenticationManager.authenticate(token).
4
ProviderManager delegates to DaoAuthenticationProvider.
5
DaoAuthenticationProvider invokes UserDetailsService.loadUserByUsername() to fetch user record from DB.
6
PasswordEncoder.matches() compares raw submitted password against stored BCrypt hash.
7
On match, a fully authenticated Authentication object (containing roles/authorities) is created.
8
Spring Security stores this Authentication object inside SecurityContextHolder.getContext().

6. Authorization Flow

Once authentication is complete, Spring Security enforces access rules on endpoints and methods:

Roles vs. Authorities

GrantedAuthority: A granular permission string (e.g. READ_USER, WRITE_ORDER).
Role: A group of authorities prefixed automatically with ROLE_ (e.g. ROLE_ADMIN, ROLE_CUSTOMER).

Request vs Method Authorization

Request Authorization: Configured globally in SecurityFilterChain using requestMatchers("/api/admin/**").hasRole("ADMIN").
Method Security: Configured on specific service methods using @PreAuthorize("hasRole('ADMIN')").

8. Password Encoding & BCrypt

Passwords must NEVER be stored in plain text or encrypted with two-way reversible algorithms. They must be hashed using one-way adaptive hashing functions containing random salt.

Why BCrypt?

BCrypt uses a key setup algorithm that includes a configurable Work Factor (Cost). This makes password verification intentionally CPU-intensive, rendering brute-force dictionary attacks and GPU hardware cracking attempts infeasible.

Salt Functionality

BCrypt automatically generates a unique random 16-byte salt per password and prepends it to the hashed output. Even if two users have identical passwords ("password123"), their resulting BCrypt hashes are completely different!

@Bean
public PasswordEncoder passwordEncoder() {
    // Standard strength cost of 10-12 recommended for production
    return new BCryptPasswordEncoder(12);
}

9. JWT (JSON Web Token) Deep Dive

JWT is an open standard (RFC 7519) defining a compact, self-contained way to securely transmit information between parties as a digitally signed JSON object.

Structure of a JWT Token (Header.Payload.Signature)

1
Header (Base64Url): Contains algorithm type ({"alg": "HS256", "typ": "JWT"}).
2
Payload (Base64Url): Contains claims ({"sub": "123456", "role": "ROLE_ADMIN", "exp": 1700000000}).
3
Signature: Cryptographic hash generated via HMACSHA256(base64(Header) + "." + base64(Payload), secretKey).
Refresh Tokens & Blacklisting:
Access tokens should be short-lived (e.g. 15 minutes). When expired, clients send a long-lived Refresh Token (stored securely in DB/Redis) to fetch a new access token. If a user logs out, their Refresh Token is deleted from DB/Redis, revoking session access.

10. OAuth2 Architecture

OAuth2 is an authorization framework that enables third-party applications to obtain limited access to a user's account on an HTTP service (e.g. "Log in with Google / GitHub").

Resource Owner: The user who owns the data.
Client: The third-party application requesting access.
Authorization Server: The server issuing tokens (e.g. Google Auth).
Resource Server: The backend API storing protected data.

Authorization Code Grant Flow

User → Clicks "Login with Google" → Redirected to Google Auth Server → User Grants Permission → Google returns Authorization Code to Client → Client exchanges Code for Access Token via backend channel → Client queries Resource Server with Access Token.

11. Session vs JWT Comparison

Dimension Stateful Session (JSESSIONID) Stateless JWT (Bearer Token)
Server State Stateful (Session stored in RAM/Redis) Stateless (No server session memory required)
Scalability Requires sticky sessions or Redis cluster Effortless horizontal microservice scaling
Revocation Instant (Delete session from server) Harder (Requires blacklist or wait for expiry)
Mobile App Friendly Requires complex cookie handling Native fit for Mobile & Single Page Apps (SPA)

12. CSRF Defense

Cross-Site Request Forgery (CSRF) tricks a user's browser into executing unwanted actions on a trusted site where they are currently authenticated via cookies.

When to Keep vs Disable CSRF:
• KEEP CSRF ENABLED: For traditional web applications using browser cookies (JSESSIONID) and HTML forms.
• DISABLE CSRF (http.csrf(csrf -> csrf.disable())): For stateless REST APIs using Authorization: Bearer <JWT> headers, because browsers do not attach JWT headers automatically on cross-site requests!

13. CORS Configuration

Cross-Origin Resource Sharing (CORS) is a browser security mechanism that restricts web pages from making API requests to a different domain/port than the one that served the web page.

@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOrigins(List.of("https://devvault.com"));
    config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE"));
    config.setAllowedHeaders(List.of("Authorization", "Content-Type"));
    
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return source;
}

14. Method Security

Enables declarative SpEL authorization directly on service layer methods using @EnableMethodSecurity.

@Service
public class UserService {

    @PreAuthorize("hasRole('ADMIN') or #userId == authentication.principal.id")
    public UserDto getUserProfile(Long userId) {
        return userRepository.findDtoById(userId);
    }
}

15. Security Configuration

Modern Spring Security (v6+) uses a component-based configuration approach defining a SecurityFilterChain bean:

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/v1/auth/**").permitAll()
                .requestMatchers("/api/v1/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated()
            )
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);
            
        return http.build();
    }
}

16. Exception Handling

Handling security errors cleanly in REST APIs:

  • AuthenticationEntryPoint (401 Unauthorized): Triggered when an unauthenticated user tries to access a protected resource.
  • AccessDeniedHandler (403 Forbidden): Triggered when an authenticated user lacks the required role/authority.

17. Production JWT Authentication Flow

Stateless JWT Request Lifecycle

1. Client sends POST /api/v1/auth/login → 2. Service validates user & generates JWT → 3. Client stores JWT in memory/HttpOnly cookie → 4. Subsequent requests attach Authorization: Bearer <token> → 5. Custom JwtFilter parses token, extracts user roles, and populates SecurityContextHolder → 6. Request proceeds to Controller.

18. Common Security Vulnerabilities

1. SQL Injection

Prevented using Spring Data JPA parameterized queries instead of string concatenation.

2. XSS (Cross-Site Scripting)

Prevented by escaping output text and setting Content-Security-Policy headers.

3. Clickjacking

Prevented by Spring Security sending X-Frame-Options: DENY headers by default.

4. Brute Force

Mitigated using BCrypt cost factor and IP rate-limiting filters (e.g., Bucket4j/Redis).

19. Senior Best Practices

  • Always use BCrypt (strength 12+) for password hashing.
  • Set short expiration times on JWT access tokens (15-30 mins) and use refresh tokens.
  • Store JWT signing keys securely using environment variables or Secret Managers (AWS Secrets Manager/Vault).
  • Enforce Least Privilege principal access on method security.

20. Common Production Mistakes

1. Storing Plaintext Secrets in Code: Hardcoding JWT secret keys inside application.properties or GitHub.

2. Using long-lived JWTs: Issuing JWT access tokens valid for days/months with no revocation mechanism.

3. Permitting All Requests on Endpoints: Misconfiguring requestMatchers("/**").permitAll() by mistake.

21. Real Production Project Stack

// Custom JWT Filter Implementation
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        
        String authHeader = req.getHeader("Authorization");
        if (authHeader != null && authHeader.startsWith("Bearer ")) {
            String jwt = authHeader.substring(7);
            if (jwtProvider.validateToken(jwt)) {
                Authentication auth = jwtProvider.getAuthentication(jwt);
                SecurityContextHolder.getContext().setAuthentication(auth);
            }
        }
        chain.doFilter(req, res);
    }
}

22. 75+ Interview Questions

Q1: What is the difference between Authentication and Authorization?
Authentication verifies WHO you are (Identity). Authorization verifies WHAT you can access (Permissions/Roles).
Q2: How does Spring Security work internally?
It uses a chain of Servlet Filters (SecurityFilterChain) managed by DelegatingFilterProxy that intercepts HTTP requests before they reach the DispatcherServlet.
Q3: What is SecurityContextHolder?
A ThreadLocal-based container that stores the current thread's SecurityContext containing the authenticated User's Authentication object.
Q4: Why use BCryptPasswordEncoder over MD5 or SHA-256?
MD5 and SHA-256 are fast hash functions vulnerable to GPU brute-force attacks. BCrypt includes a cost factor that makes hashing intentionally slow and incorporates salt automatically.
Q5: What is the difference between OAuth2 and JWT?
OAuth2 is an authorization framework specifying how tokens are issued. JWT is a token format specification. OAuth2 often uses JWTs as access tokens.
Q6: What is DelegatingFilterProxy?
A standard Servlet Filter that bridges the Servlet container to Spring-managed FilterChainProxy beans.
Q7: What is AuthenticationManager?
The main interface that processes authentication requests; default implementation is ProviderManager.
Q8: What is UserDetailsService?
A core interface with a single method (loadUserByUsername) used to load user data from a database or store.
Q9: What is UserDetails?
An interface representing user identity details (username, password, granted authorities, account status).
Q10: Difference between 401 Unauthorized and 403 Forbidden?
401 means unauthenticated (missing or invalid credentials). 403 means authenticated but lacking required permissions.
Q11: What is CSRF and how do you protect against it?
Cross-Site Request Forgery tricks browsers into sending forged cookie requests. Protected using anti-CSRF tokens.
Q12: When should CSRF protection be disabled?
In stateless REST APIs that use Bearer JWT tokens attached in Authorization headers rather than browser cookies.
Q13: What is CORS?
Cross-Origin Resource Sharing—a browser security feature that restricts cross-domain HTTP requests unless permitted by server headers.
Q14: What is a CORS Preflight Request?
An automatic HTTP OPTIONS request sent by browsers to verify server CORS permissions before sending actual requests.
Q15: How to enable method security in Spring Boot 3?
Add @EnableMethodSecurity on a configuration class and use @PreAuthorize on methods.
Q16: Difference between @PreAuthorize and @Secured?
@PreAuthorize supports full SpEL expressions; @Secured is a legacy annotation that only accepts simple role strings.
Q17: What are the three parts of a JWT?
Header (algorithm), Payload (claims), and Signature (cryptographic hash).
Q18: How do you invalidate a JWT before its expiration?
Maintain a token blacklist in Redis, or use short-lived access tokens with revocable Refresh Tokens.
Q19: What is GrantedAuthority?
An individual permission or role string assigned to an authenticated user.
Q20: What is AuthenticationEntryPoint?
An interface invoked when an unauthenticated request attempts to access a protected resource (returns 401).
Q21: What is AccessDeniedHandler?
An interface invoked when an authenticated user lacks required permissions (returns 403).
Q22: Difference between Role and Authority in Spring Security?
Roles are prefixed with "ROLE_" (ROLE_ADMIN). Authorities are fine-grained strings (READ_PRIVILEGE).
Q23: How does OncePerRequestFilter work?
Guarantees that a custom filter executes exactly once per HTTP request dispatch.
Q24: What is SecurityContextPersistenceFilter?
Legacy filter that loaded and saved SecurityContext to HTTP Session across requests.
Q25: What is SessionCreationPolicy.STATELESS?
Tells Spring Security never to create or use HTTP sessions (ideal for JWT REST APIs).
Q26: What is OAuth2 Resource Server?
An API server that accepts and validates OAuth2 access tokens to serve protected data.
Q27: What is OAuth2 Authorization Server?
The server that authenticates users and issues access tokens (e.g., Keycloak, Okta, Auth0).
Q28: What is Authorization Code Grant in OAuth2?
The most secure OAuth2 flow where an authorization code is exchanged for an access token via back-channel.
Q29: What is Client Credentials Grant in OAuth2?
A server-to-server OAuth2 flow where an app authenticates using its own credentials without user context.
Q30: How to prevent SQL Injection in Spring applications?
Use Spring Data JPA parameterized queries and avoid concatenating raw strings in SQL statements.
Q31: What is XSS and how to prevent it?
Cross-Site Scripting inserts malicious JS scripts. Prevented by escaping input/output and configuring CSP headers.
Q32: What is Clickjacking and how does Spring prevent it?
Tricking users into clicking transparent iframe elements. Spring sets 'X-Frame-Options: DENY' headers.
Q33: What is Session Fixation?
An attack where an attacker sets a known session ID. Spring protects by creating a new session ID on login.
Q34: What is AnonymousAuthenticationToken?
An Authentication object representing an unauthenticated guest user in the SecurityContext.
Q35: How to configure method security for specific SpEL expressions?
Using @PreAuthorize("hasAuthority('WRITE') and #entity.owner == authentication.name").
Q36: What is DaoAuthenticationProvider?
Default AuthenticationProvider that uses UserDetailsService and PasswordEncoder to authenticate credentials.
Q37: Where should JWT access tokens be stored on frontend?
In-memory variables (safest from XSS) or HttpOnly SameSite cookies (safe from XSS & CSRF).
Q38: Why should JWT secret keys be at least 256 bits?
HS256 signature algorithms require minimum 256-bit (32 byte) keys to prevent brute-force key cracking.
Q39: What is OpenID Connect (OIDC)?
An identity layer built on top of OAuth2 that provides ID tokens for user profile information.
Q40: How to test Spring Security endpoints in integration tests?
Using @WithMockUser(roles = "ADMIN") annotation in Spring Test.
Q41: What is SecurityContextHolder strategy?
Defines how SecurityContext is stored (MODE_THREADLOCAL by default, or MODE_INHERITABLETHREADLOCAL for async threads).
Q42: What is UsernamePasswordAuthenticationToken?
A standard implementation of Authentication used for username/password credential processing.
Q43: What is the purpose of @EnableWebSecurity?
Enables Spring Security's web security support and imports Spring MVC integration configurations.
Q44: How to permit access to public endpoints without auth?
Using requestMatchers("/public/**").permitAll() in SecurityFilterChain.
Q45: What happens if an unhandled Exception occurs in a custom Security Filter?
It bypasses Spring MVC @RestControllerAdvice and must be caught inside the filter or by ExceptionTranslationFilter.
Q46: What is Spring Security's ExceptionTranslationFilter?
A filter that catches SecurityExceptions and delegates to AuthenticationEntryPoint or AccessDeniedHandler.
Q47: Can a application have multiple SecurityFilterChain beans?
Yes! Ordered by @Order annotation, allowing separate security chains for /api/** and /admin/** endpoints.
Q48: How to retrieve current logged in user in a Controller method?
By injecting @AuthenticationPrincipal UserDetails user or inspecting SecurityContextHolder.
Q49: What is PasswordEncoder.matches()?
Compares raw unhashed password input against an existing encoded hash to check for validity.
Q50: What is the main architectural takeaway of Spring Security?
Servlet Filter Chain delegation, ThreadLocal context storage, adaptive BCrypt hashing, and stateless JWT/OAuth2 support.

23. Revision Cheatsheet

Authentication: WHO you are (401) · Authorization: WHAT you can do (403).

Filter Chain: DelegatingFilterProxy → FilterChainProxy → SecurityFilterChain filters.

Context Storage: SecurityContextHolder.getContext().getAuthentication() (ThreadLocal).

BCrypt: Hashing with automatic 16-byte salt and cost factor strength.

JWT Structure: Header.Payload.Signature (Base64Url encoded & HMAC signed).

CORS: Browser cross-domain restriction · CSRF: Cookie forgery protection.
