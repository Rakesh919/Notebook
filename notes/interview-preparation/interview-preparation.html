☕ PART 3 — Core Java In-Depth

1. Object-Oriented Programming (OOP) Deep Dive

Must Know

Infosys interviewers look for practical intuition rather than dictionary definitions:

  • Encapsulation: Wrapping data (fields) and code (methods) together into a single unit and restricting direct access (data hiding) using private access modifiers and getters/setters. Example: BankAccount with private balance accessed through validated deposit() method.
  • Abstraction: Hiding internal implementation complexity and showing only essential functionality to the user. Achieved via Abstract Classes and Interfaces. Example: JDBC Connection interface; users execute queries without knowing the underlying vendor driver byte-handling.
  • Inheritance: Mechanism where a child class acquires properties and behaviors of a parent class (extends), promoting code reuse. Example: class SavingsAccount extends Account.
  • Polymorphism: The ability of an object to take many forms.
    • Compile-time (Static / Method Overloading): Same method name, different parameter signature in the same class.
    • Runtime (Dynamic / Method Overriding): Subclass overrides parent method with exact same signature and @Override annotation. Resolved at runtime using dynamic method dispatch.
Q: Can we override a private or static method in Java?
No. Private methods are not visible outside the class (no dynamic dispatch). Static methods belong to the class, not instances; declaring the same static method in a subclass is called Method Hiding, not method overriding.

3. String Immutability, String Pool & Mutability

Must Know

Strings are immutable in Java (once created, their internal char[]/byte[] cannot change). String literals reside in the String Constant Pool (SCP) located in the heap.

String s1 = "Infosys";               // Allocated in String Constant Pool
String s2 = "Infosys";               // Reuses instance from SCP -> s1 == s2 (TRUE)
String s3 = new String("Infosys");   // Forces new object in Heap -> s1 == s3 (FALSE)
s3 = s3.intern();                   // Returns SCP reference -> s1 == s3 (TRUE)

Why String is Immutable: Security (storing DB credentials/URLs safely), Thread Safety (inherently thread-safe without synchronization), Caching (hashCode can be cached at creation), String Pool efficiency.

4. equals() and hashCode() Contract

Must Know

The contract defined in java.lang.Object states:

  1. If o1.equals(o2) == true, then o1.hashCode() == o2.hashCode() MUST be true.
  2. If o1.hashCode() == o2.hashCode(), o1.equals(o2) may or may not be true (Hash Collision).
  3. If you override equals(), you MUST override hashCode(). Failing to do so breaks hash-based collections (HashMap, HashSet).

5. Java Exception Hierarchy

High Priority
Throwable→ Error (OutOfMemoryError, StackOverflowError - Non-recoverable)
Throwable→ Exception→ Checked (IOException, SQLException - Verified at compile time)
Throwable→ Exception→ RuntimeException (Unchecked: NullPointerException, ArithmeticException)

final vs finally vs finalize:

  • final: Keyword to make variable constant, method non-overridable, class non-inheritable.
  • finally: Block following try-catch executed guaranteed (except system crash/System.exit(0)). Used for resource cleanup (better replaced by try-with-resources).
  • finalize(): Deprecated method called by Garbage Collector before reclaiming memory.

🗝️ PART 4 — HashMap Internal Working (MUST KNOW)

The Exact Put/Get Pipeline:

Key Object→ key.hashCode()→ hash() spread→ Index = (n-1) & hash→ Bucket Array (Node<K,V>[])→ equals() check
Q: Walk me through what happens when map.put("key", value) is called.
1. HashMap calculates hashCode() of the key and applies bitwise spreading: hash = (h = key.hashCode()) ^ (h >>> 16).
2. Calculates array index: index = (n - 1) & hash (where n is current array capacity, default 16).
3. If bucket is empty: A new Node<K,V> is stored directly in that bucket.
4. If collision occurs (bucket occupied): It iterates the linked list or red-black tree in that bucket:
  • If an existing node has matching hash and (node.key == key || key.equals(node.key)), the existing value is replaced.
  • If no match is found, the new node is appended to the tail.
5. Java 8 Treeification: When linked list length in a bucket exceeds 8 AND overall capacity ≥ 64, the list converts into a Red-Black Tree (improves search from O(n) to O(log n)).
6. If size exceeds threshold (capacity * loadFactor = 16 * 0.75 = 12), the array doubles in capacity (Resizing/Rehashing).

Intermediate vs Terminal Operations & map vs flatMap

High Priority

Intermediate Operations (e.g., filter(), map(), sorted()) return a new Stream and are lazily evaluated (they do not execute until a terminal operation is called). Terminal Operations (e.g., collect(), forEach(), count(), reduce()) initiate stream processing and produce a non-stream result.

map() vs flatMap():

  • map(): 1-to-1 transformation. Input Stream<T> → Output Stream<R>.
  • flatMap(): 1-to-Many flattening. Input Stream<List<String>> → Flattens into Stream<String>.

🚀 PART 8 - 12 — Spring Framework & Spring Boot Ecosystem

IoC, Dependency Injection & Constructor Injection

Must Know

Inversion of Control (IoC): Inverting the control of object creation and lifecycle from the developer to the Spring Container (ApplicationContext).

Dependency Injection (DI): The pattern where the IoC container injects dependent objects into a class.

Q: Why is Constructor Injection preferred over Field Injection (@Autowired on field)?
1. Immutability: Allows declaring dependencies as final.
2. Testability: Makes Unit Testing trivial (you can instantiate the class and pass mock dependencies with plain Java new without needing Spring test reflection).
3. Avoids NullPointerExceptions: Ensures the object is never created in an uninitialized, invalid state at runtime.

Global Exception Handling Pattern

Must Know
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(ResourceNotFoundException ex) {
        ErrorResponse err = new ErrorResponse(HttpStatus.NOT_FOUND.value(), ex.getMessage(), System.currentTimeMillis());
        return new ResponseEntity<>(err, HttpStatus.NOT_FOUND);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, String>> handleValidationErrors(MethodArgumentNotValidException ex) {
        Map<String, String> errors = new HashMap<>();
        ex.getBindingResult().getFieldErrors().forEach(error -> 
            errors.put(error.getField(), error.getDefaultMessage()));
        return new ResponseEntity<>(errors, HttpStatus.BAD_REQUEST);
    }
}

💾 PART 13 - 15 — JPA, Hibernate & Transactions

Entity Lifecycle States & N+1 Problem

Must Know

Core distinction: JPA is the specification (interfaces); Hibernate is the actual ORM implementation.

Entity Lifecycle:

Transient (new Object())→ Persistent (em.persist() / In Session)→ Detached (Session closed / clear())→ Removed (em.remove())
Q: What is the Hibernate N+1 Problem and how do you solve it?
The Problem: When loading 1 parent entity with N child entities under FetchType.LAZY (or eager iteration), Hibernate executes 1 query to fetch the parent list, and then N separate SQL queries to fetch the associated children for each parent row.
The Solution: Use JOIN FETCH in JPQL or @EntityGraph: 
// Solution via JPQL Join Fetch:
@Query("SELECT d FROM Department d JOIN FETCH d.employees")
List<Department> findAllWithEmployees();

@Transactional Propagation Levels

High Priority

📊 PART 16 — SQL Mastery (Designed for Weak Area Recovery)

Logical SQL Query Execution Order

Crucial Mental Model

SQL is not executed top-to-bottom as written. SQL engines process clauses in this exact sequence:

1. FROM & JOIN→ 2. WHERE (Row filter)→ 3. GROUP BY→ 4. HAVING (Group filter)→ 5. SELECT→ 6. DISTINCT→ 7. ORDER BY→ 8. LIMIT / OFFSET
Q: Difference between WHERE and HAVING clause?
• WHERE filters individual rows BEFORE aggregation/grouping occurs. Cannot use aggregate functions (WHERE COUNT(*) > 5 is INVALID).
• HAVING filters aggregated groups AFTER GROUP BY is performed (HAVING COUNT(*) > 5 is VALID).

Must-Memorize Infosys SQL Queries & Solutions

1. Second Highest Salary (2 Classic Approaches)
-- Approach A (Subquery - Safe against duplicates):
SELECT MAX(salary) FROM Employee 
WHERE salary < (SELECT MAX(salary) FROM Employee);

-- Approach B (LIMIT / OFFSET):
SELECT DISTINCT salary FROM Employee 
ORDER BY salary DESC 
LIMIT 1 OFFSET 1;

-- Approach C (Generic Nth Highest Salary using DENSE_RANK):
SELECT salary FROM (
    SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) as rnk 
    FROM Employee
) ranked WHERE rnk = 2;
2. Find and Delete Duplicate Records (Keep lowest ID)
-- Find duplicate emails:
SELECT email, COUNT(*) FROM Employee 
GROUP BY email 
HAVING COUNT(*) > 1;

-- Delete duplicates keeping the minimum id:
DELETE FROM Employee 
WHERE id NOT IN (
    SELECT MIN(id) FROM Employee GROUP BY email
);
3. Find Departments with More Than 5 Employees
SELECT d.dept_name, COUNT(e.id) AS emp_count
FROM Department d
JOIN Employee e ON d.id = e.department_id
GROUP BY d.dept_name
HAVING COUNT(e.id) > 5;
4. Employees Earning More Than Department Average
SELECT e.name, e.salary, e.department_id
FROM Employee e
WHERE e.salary > (
    SELECT AVG(salary) 
    FROM Employee 
    WHERE department_id = e.department_id
);

🔒 PART 17 - 19 — Spring Security, JWT & OAuth 2.0

Security Filter Chain & JWT Lifecycle

Must Know

JWT (JSON Web Token) Structure: Header.Payload.Signature

  • Header: Alg type (HS256) & Token type (JWT).
  • Payload: Claims (Subject, Expiration, Roles). Base64Url encoded (NOT encrypted, never store passwords here!).
  • Signature: HMACSHA256(base64Url(header) + "." + base64Url(payload), secretKey). Guarantees token integrity.

Security Request Filter Pipeline:

HTTP Request (Header: "Bearer <token>")→ JwtAuthenticationFilter (OncePerRequestFilter)→ Validate Signature & Expiry→ Load UserDetails→ Set SecurityContextHolder→ Controller
JWT vs Session
Session: Stateful, stored on server memory/Redis, doesn't scale horizontally easily.
JWT: Stateless, self-contained, validated on every microservice via signature verification without DB roundtrip.
JWT vs OAuth 2.0
JWT: A token format.
OAuth 2.0: An authorization framework/protocol specifying how third-party apps acquire tokens (e.g., "Login with Google").

Microservices Core Components

High Priority
  • Service Discovery (Netflix Eureka): Dynamic registry where microservices register their IP/port and discover downstream instances.
  • API Gateway (Spring Cloud Gateway): Single entry point for routing, rate limiting, authentication filtering, and CORS.
  • Circuit Breaker (Resilience4j): Prevents cascading failures when downstream services are dead (States: Closed → Open → Half-Open).
  • Distributed Transactions (Saga Pattern): Manages data consistency across independent microservice databases using a series of local transactions and compensating transactions for rollbacks.

Apache Kafka Essentials

Interview Focus

Kafka is an append-only distributed event commit log.

  • Topic & Partitions: Topics are split into partitions for parallelism. Partitions are the unit of scalability and order guarantee.
  • Offset: Unique sequential ID given to each message within a partition.
  • Consumer Group: Set of consumers cooperating to read a topic. Rule: Each partition in a topic is consumed by only ONE consumer within a consumer group at any time.
// Simple Spring Boot Producer:
@Service
public class OrderProducer {
    @Autowired private KafkaTemplate<String, OrderEvent> kafkaTemplate;
    public void sendOrder(OrderEvent event) {
        kafkaTemplate.send("order-topic", event.getOrderId(), event);
    }
}

// Simple Spring Boot Consumer:
@Service
public class OrderConsumer {
    @KafkaListener(topics = "order-topic", groupId = "order-notification-group")
    public void consume(OrderEvent event) {
        System.out.println("Processing order: " + event.getOrderId());
    }
}

Redis & Cache-Aside Pattern

Interview Focus

Cache-Aside Pattern Flow:

App checks Redis→ Hit: Return Cached Data
Miss: Query DB→ Store result in Redis with TTL→ Return Response 
@Service
public class UserService {
    @Cacheable(value = "users", key = "#id") // Caches result automatically
    public User getUserById(Long id) {
        return userRepository.findById(id).orElseThrow();
    }

    @CacheEvict(value = "users", key = "#user.id") // Evicts cached entry on update
    public User updateUser(User user) {
        return userRepository.save(user);
    }
}

🧪 PART 23 & 24 — Unit Testing: JUnit 5 & Mockito

Golden Rule: JUnit 5 is the test execution runner and assertion framework; Mockito is the mocking library to isolate dependencies.

@ExtendWith(MockitoExtension.class)
public class UserServiceTest {

    @Mock
    private UserRepository userRepository; // Mocked dependency

    @InjectMocks
    private UserServiceImpl userService;  // Injects mock into actual service

    @Test
    void testGetUserById_Success() {
        // Given (Stubbing)
        User mockUser = new User(1L, "Alice");
        Mockito.when(userRepository.findById(1L)).thenReturn(Optional.of(mockUser));

        // When (Execution)
        User result = userService.getUserById(1L);

        // Then (Assertions & Verifications)
        Assertions.assertEquals("Alice", result.getName());
        Mockito.verify(userRepository, Mockito.times(1)).findById(1L);
    }
}

💻 PART 25 — Top Algorithm Coding Questions

1. Two Sum Problem (O(n) Time Complexity)
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> map = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (map.containsKey(complement)) {
            return new int[]{map.get(complement), i};
        }
        map.put(nums[i], i);
    }
    throw new IllegalArgumentException("No match");
}
2. Check If String is Palindrome
public boolean isPalindrome(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
        if (s.charAt(left++) != s.charAt(right--)) return false;
    }
    return true;
}
3. Find Missing Number in Array [1 to N]
public int findMissing(int[] arr, int n) {
    int expectedSum = n * (n + 1) / 2;
    int actualSum = Arrays.stream(arr).sum();
    return expectedSum - actualSum;
}

🚨 PART 26 — 10 Practical Production Scenarios

Scenario 1: An API is taking 5 seconds. How would you debug it?
1. Check API Gateway logs and distributed tracing (Zipkin/Sleuth) to isolate which service or DB call is the bottleneck.
2. Enable Hibernate SQL logging (spring.jpa.show-sql) and verify if N+1 queries or unindexed table scans are occurring.
3. Check DB thread pool/connection pool exhaustion (HikariCP).
4. Implement Redis caching for read-heavy static data.
Scenario 2: Downstream Microservice is Down/Failing
Apply Circuit Breaker (Resilience4j) to short-circuit requests and provide fallback graceful degradation (cached response or user friendly error) instead of exhausting system threads.
Scenario 3: Kafka Consumer is Processing Duplicate Messages
Kafka guarantees at-least-once delivery by default. Consumers MUST be idempotent: store processed message IDs in a DB table or Redis cache. Before processing, check if messageId exists; if yes, acknowledge and skip.

🔥 PART 29 & 30 — TOP 50 Rapid Revision & Must-Know Qs

1. Is HashMap thread-safe?
No. Use ConcurrentHashMap for thread safety.
2. Can HashMap store null key?
Yes, exactly one null key (stored at index 0).
3. What is functional interface?
An interface containing exactly one abstract method (can have multiple default/static methods).
4. What is default method?
Method in interface with default implementation using default keyword, preserving backward compatibility.
5. @SpringBootApplication consists of?
@Configuration, @EnableAutoConfiguration, @ComponentScan.
6. How does Hibernate 1st level cache work?
Session-scoped by default. Queries for same entity ID in same transaction hit memory cache instead of DB.
7. What is JWT signature used for?
Verifying that the token payload has not been tampered with in transit.
8. What is LazyInitializationException?
Occurs when accessing a lazy-loaded collection after the Hibernate Session has already closed.
